# FlowExecutor 全核重设计 —— 架构评审立项书（词条切片 C）

> 状态：**立项书**——只立设计面，本轮零代码零行为；启动编码须产品点名（defer 条款照用）。
> 依据：HEAD 态执行器头件与源件逐行普查（面索引见 §7），非估计。
> 关联：巨型类拆分立项词条 §3 切片 C（FlowExecutor 全核重设计）；该词条 §3 切片 C 段的「162 行口径」旧指代以本书 §1.2 所述实际守卫位为准（源件注释自指 P2-6 词条）。
> 性质：架构评审立项，非随轮拆任务——本书给出结论、方案对比、风险登记与分期路线，不动一行代码。

## 0. 一页速览（结论先行）

| 项 | 结论 |
|---|---|
| 终局形状 | 执行器与图形状态的**所有权**重构：节点、连线、快照三项从裸指针改为共享所有权；随之才可能撤掉「析构时中止进程」这一终局护栏 |
| 是不是一次重构 | 不是。属**分期路线**：五期（P0 测绘与护栏 → P1 低风险面引用计数化 → P2 快照与墓碑共享所有权化 → P3 执行器与场景强引用闭环 → P4 撤终局中止），每期独立轮、行为零变更、随时可回退 |
| 三条硬不变量 | 锁序单向、快照与墓碑语义、停稳判定（承词条 §4）；另加三条新钉（见 §6） |
| 最大现实约束 | 节点是 QObject，与父子树同生共死；**QObject 不宜由 shared_ptr 托管**——共享所有权要落地，绕不开「QObject 壳 + 非 QObject 状态体」的形态抉择（未决 O-1，需产品拍板） |
| 本书不主张 | 不主张立即编码；不主张砍掉终局中止（撤除条件见 §2.2，且需 O-2 拍板） |

## 1. 现状测绘（执行器所有权面）

### 1.1 裸指针面清单（按持有者分九族）

| 族 | 持有位置 | 形态 | 风险位 |
|---|---|---|---|
| 场景指针 | 执行器成员 | 场景裸指针 | 场景先亡即悬垂（析构段已做后置清空处理） |
| 缓存键（指针维） | 执行器成员 | 节点指针作键的映射两族 | 节点被删后键悬垂（已由账簿与墓碑机制间接护住） |
| 缓存键（模块号维） | 执行器成员 | 模块号作键的映射一族 | 无指针风险，语义为「按模块号清」 |
| 图索引 | 执行器成员 | 节点指针 → 连线裸指针两族 | 同缓存键族 |
| 执行队列与集合 | 执行器成员 | 节点指针队列与集合多族 | 轮内私有，靠快照隔离 |
| 账簿键 | 账簿面 | 节点指针仅作键、模块号随行 | **键用即止**纪律（键比较不触内存、不解除引用）——已由切片 A 落座并立座钉死 |
| 节点归属指针 | 节点成员 | 执行器裸指针 | 写三处、读七处（四类节点 + 全局单例兜底）；执行器销毁窗口内可能悬垂（析构段已做后置清空） |
| 触发注册 | 全局触发管理器 | 执行器裸指针 | 登记/注销成对，析构内注销 |
| 全局单例 | 执行器静态 | 原子裸指针 | 析构置空，读侧有兜底但仍为裸读 |

### 1.2 生命周期与终局护栏

- 正常销毁路径：调用方先「停止并在超时内等待线程真正退出」，再析构（主窗侧有专门的回收件与泄漏保护路径）。
- 析构内两段有界等待（一段 5 秒、二段 15 秒，二段前重停一轮），两段皆尽才进终局：先过应用层收尾钩子（把方案与日志收好的一格，默认空），**返回后中止进程**。
- 源码注释自指：「全砍中止需全核 shared_ptr 化重设计，属 P2-6 词条」——即本书所立的切片 C。
- 析构后置动作：把活节点的归属指针清空（避免执行器已死、节点仍指向它）；读侧共四处分布在四类节点里。
- 收尾钩子与两段阈值都是常量口径，改动它们属行为变更，不在本书范围。

### 1.3 图快照与墓碑机制（执行期隔离）

- 快照值类型：两列裸指针（节点列、连线列），不含图元。
- 快照句柄是 RAII 句柄：持有期间，从图中删除节点或连边**只做墓碑**（成员集立即摘除 + 延迟析构），保证执行线程手里那批裸指针在整轮结束前不悬垂；句柄析构（含提前返回、异常、跳出）即释放。
- 墓碑队列在场景侧，**真析构只在场景线程执行**（绝不从工作线程析构节点）。
- 同一时刻只允许执行线程持有一个句柄（执行器单线程；界面侧同步执行为单发）。

### 1.4 锁面

| 锁 | 保护对象 | 纪律 |
|---|---|---|
| 状态锁 | 执行状态与等待点 | 等待点内持锁；停进即发「图已停稳」信号 |
| 图锁 | 缓存三族与图索引五族 | 粒度最细，绝不跨越会再触碰缓存的调用 |
| 统计锁 | 统计读写（执行线程写、界面线程读） | 独立短窗 |
| 账叶锁 | 登记账 | **叶子无后沿**：持锁期间不得再取任何别的锁 |

锁序单向：执行器图锁 → 账叶锁；反向即死锁环（既有走查结论在案）。

### 1.5 已知悬垂窗口（源码自陈）

- 执行器析构窗口内，节点里的归属指针可能悬垂——现状用「析构后置清空活节点归属指针」收敛，窗口本身仍在。
- 账簿里的键「用即止」：入账后节点可能已析构，键比较不碰内存。

## 2. 目标形状（评审用）

### 2.1 三项共享所有权

1. **节点**：执行期所见节点由快照以共享所有权持有；场景是唯一强 owner，删除走墓碑（成员集摘除 + 引用归零才真析构）。
2. **连线**：随节点同生共死，连接件由端口侧或场景侧共享持有。
3. **快照**：快照句柄本身即共享所有权的载体（释放即引用计数减一）。

### 2.2 撤掉终局中止的三个必要条件（三条同时达成才谈撤除）

- **T1**：工作线程不再通过执行器主体访问任何可能被提前释放的状态（快照与缓存自持其生命周期）。
- **T2**：不再存在「绕过等待直接销毁执行器」的路径（销毁权收归唯一 owner，界面侧只调停止与等待）。
- **T3**：等待超时不再必须中止进程——改为「中止执行器并进入可观测终态（停止流程、报错、留现场）」，其对外语义由产品拍板（未决 O-2）。

> 关键洞见：**终局中止与悬垂读面同根**（根因是「工作线程仍会读执行器主体」）。因此只在悬垂面上打补丁（如世代号、令牌）的弱化方案**无法撤除终局中止**——这是本评审否掉弱化案单独成立的核心理由。

### 2.3 锁序在新形状下的映射

共享所有权化后，取锁顺序与引用增减顺序可能交叉。硬要求：引用计数的增减**不得**发生在持其他锁的临界区内（与既有「图锁 → 账叶锁」单向纪律同性质）。

## 3. 方案对比

| 维度 | 案 A：全量共享化 | 案 B：分层共享（推荐） | 案 C：弱化过渡 |
|---|---|---|---|
| 形态 | 节点、连线、快照、缓存键全部共享所有权 | 场景持节点强引用；执行器只持「共享的快照」；缓存键仍按现行口径（键用即止） | 不动所有权；加世代号与生命周期令牌，收敛悬垂读面 |
| 改动面 | 极大：全部节点类与端口与连接件 | 中：节点状态体 + 快照 + 场景墓碑三处 | 小：加字段与断言 |
| 能否撤终局中止 | 能（若 T1/T2/T3 齐备） | 能（T1/T2 需配合 P3；T3 待拍板） | **不能**（与终局中止同根，见 §2.2 洞见） |
| 现实约束命中 | 直撞 QObject 父子树与共享所有权冲突 | 同样命中，但可把「壳与状态体分离」限定在少数基类 | 不命中 |
| 可回退性 | 低（一旦全量共享化，回退面极大） | 高（分期，每期独立可退） | 高 |
| 验证手段 | 长周期回归为主 | 红绿臂自证 + 新座双注册 + 宿主整轮 | 断言与座为主 |

**推荐案 B**，且以「分期 + 每期行为零变更」为前提。案 C 可作为 P1 的过渡护栏与案 B 的并行副线，但不单独承担终局目标。

## 4. 风险登记

| 号 | 风险 | 证据位 | 缓解 |
|---|---|---|---|
| R1 | QObject 父子树与共享所有权冲突（节点不可由 shared_ptr 托管） | 节点均为 QObject 派生、场景持成员集并直接析构 | P2 之前先定「壳 + 非 QObject 状态体」是否可接受（O-1）；未决前不动节点基类 |
| R2 | 锁序成环（引用增减与取锁交叉） | 既有锁序单向纪律 | 每期做锁序走查；引用增减不落持锁临界区（§2.3） |
| R3 | 墓碑堆积（快照持有期被拉长导致真析构推迟） | 墓碑队列在场景侧、flush 在场景线程 | 快照持有期不变列为硬不变量（V2）；另加墓碑队列长度监控 |
| R4 | 跨线程析构亲和性（引用归零线程可能是工作线程） | 现有纪律：真析构只在场景线程 | 墓碑真析构仍在场景线程（纪律不变）；引用归零只发信号回场景线程 |
| R5 | 停稳判定与「可改图」语义漂移 | 停稳信号是改图依据 | V3 + 既有座续绿，改动须红绿臂自证 |
| R6 | 撤除终局中止后「进程活着但流程已死」被当成功 | 终局中止当前是唯一硬保底 | P4 必须同时落终态状态机 + 现场提示 + 门禁断言（不留静默失败） |
| R7 | 账簿键纪律被所有权化顺手放宽 | 账簿「键用即止」纪律已立座钉死 | V5：改键形态须另立等价纪律并单独评审 |

## 6. 不可动不变量（承词条 §4 三条 + 本书新增三条）

1. **锁序单向**：执行器图锁 → 账叶锁；反向即死锁环。
2. **快照与墓碑语义不变**：执行期隔离不破（删除只摘成员集、延迟析构；快照持有期不延长）。
3. **停稳判定不变**：停稳信号仍是唯一可改图依据。
4. **新增 V4**：终局中止形态不早于 P4 撤除；P0..P3 期间原样保留。
5. **新增 V5**：账簿「键用即止」纪律不因所有权化而放宽（改键形态须另立等价纪律并单独评审）。
6. **新增 V6**：所有权化不得改变可见图结构来源——快照仍来自场景成员集拷贝，不得改为「活图直读」。

## 9. P0 期落位（所有权契约断言座）

P0 的另一半产出（本书之外的可执行部分）已落为一座四腿断言——把「谁持谁、谁必须先释放」从注释里的约定变成回归护栏，供 P1 至 P4 逐期取「行为零变更」基线。

| 事实 | 语义 | 座腿 | 本期红臂破坏位 |
|---|---|---|---|
| ① 全局单例 | 执行器构造即登记为当前实例，析构即置空（全局单例不得指向已死对象） | 单例生命周期腿 | —— |
| ② 节点归属指针 | 执行器析构时把仍活着的节点的归属指针清空（已死执行器不在节点上留悬垂指向） | 析构后清归属腿 | **本期破坏位**：移除析构内该段即此腿红 |
| ③ 解绑不清归属 | 解绑场景（置空）刻意保留节点归属指针——节点可能已转由别的执行器接管，清成空反而退回全局单例兜底 | 解绑腿 | —— |
| ④ 触发面配对 | 按执行器身份注册在触发管理器里的绑定，随执行器析构一并注销（只删同身份，不误删新注册） | 触发面腿 | —— |

- fixture：真场景 + 真节点（场景自建节点）+ 真执行器；**不启动工作线程**——本座只验所有权面，不碰执行语义。
- 本期**零业务代码改动**：仅新增座与登记。
- 红臂读数：移除析构内「活节点归属指针后置清空」段 → 全座 5 passed 1 failed，恰第二腿红，其余三腿臂内原样绿（窄破坏自证）。
- 双注册在册（构建注册与测试批注列两处）；座号四十五，测试总数 45 变 46。
- 后续期次的用法：P1 动触发注册面与全局单例与归属指针三处时，本座即其「行为零变更」的比对面（红臂破坏位须重新选定，不得沿用本期破坏位）。

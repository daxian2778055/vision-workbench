### 1.2 官方协议全集（表 5-1，手册页 81–83）

### 2.5 官方交互（9.2.2，页 183）

> 「在左侧控件区通过鼠标选中某个控件后，**按住鼠标左键不动并移动到中间的预览及编辑区**，
> 在计划摆放控件的区域松开鼠标即可完成控件添加。」

当前实现**不支持控件库→画布拖放**（全文件无 `QDrag`/`dropEvent`），只有「选中 + 添加按钮 / 双击」。
项目手册 `docs/用户操作手册.md:45,494` 写的「拖拽式搭建」指的是画布内拖动，**与官方口径不符**。

### 2.6 画布与固定栏（9.3.1）

- 画布默认单画面；选中画布可在属性区配置**基础配置 + 布局分割样式**（模板1 等）
- 固定栏上/下/左/右可多选；每个固定栏有自己的**分割模板**
- 控件拖到固定栏或画布的网格里；控件「自动填充」= 填满所在网格

当前：画布固定 1200×760、**无分割样式**、**无固定栏**、**无网格单元格概念**。
截图 2 右侧属性区的「外观 / 显示网格 / 网格颜色 / 背景」正是**画布属性**，当前无对应。

### 2.7 运行界面结论

**UI 结构 ≈ 三成**：四区域骨架在，但工具条缺 9 项、控件少 15 种、
无拖放 / 无 Ctrl+C/V / 无固定栏 / 无画布分割 / 无模板 / 属性区字段远少于官方。

## 3. 分阶段实施顺序（用户口径：先 UI 一致，功能后补）

| 批次 | 内容 | 风险 |
|---|---|---|
| **B1（本批）** | 设计器**骨架**：工具条补齐（图层 4 档、对齐 6+2、适配按钮、固定栏入口占位、模板入口占位）、控件区按官方三组分组并补齐控件名占位、属性区按「数据源/布局/外观」三折叠分组、**控件库→画布拖放**、**Ctrl+C/V**、撤销栈覆盖属性与几何 | 中：只动设计器 UI，模型/持久化兼容旧布局 |
| B2 | 固定栏（上/下/左/右）+ 画布分割模板 + 网格单元格 + 自动填充 / T/B/L/R 边距 / 九宫格对齐 | 高：影响布局模型与运行视图 |
| B3 | 控件逐个补实现（按现场需要的优先：参数设置、开关控制、Tab页、组合框、线图/饼图） | 中：每种都要绑数据 |
| B4 | 通信管理窗口形态对齐：6 项左导航合并入口、控制器列表、右下收发监视并入、gtd 导入导出 | 中 |
| B5（可选） | FINS TCP/UDP 协议（官方参数见 1.2） | 高：需真机 |

**原则**：每批只动一层，模型与持久化保持向后兼容（旧布局能加载），每批配腿 + 全量回归 + 出包。

### B1a 已落地（2026-11-09，本轮）

先做了两处**官方明确、且不改布局模型/持久化**的交互：

1. **控件库 → 画布拖放**（官方 9.2.2「按住左键移动到预览及编辑区松开」）：
   `m_palette` 开 `dragEnabled + DragOnly`、item 补 `ItemIsDragEnabled`；
   `RuntimeDesignerCanvas` 开 `setAcceptDrops(true)` 并重写 `dragEnterEvent/dropEvent`，
   只收 Qt 内建 item-model MIME（不解析私有格式），落点经钳制后作为控件左上角。
   原有「添加按钮 / 双击」两条路径保留。
2. **Ctrl+C / Ctrl+V 复制粘贴**（官方 9.1 工具条注「复制粘贴仅支持 Ctrl+C 和 Ctrl+V」）：
   剪贴板放单控件的 `RuntimeInterfacePage::toJson()`（自定义 MIME
   `application/x-vfp-runtime-control`），粘贴时 `fromJson()` 还原并级联偏移 24px、入撤销栈。
   焦点在输入框内时经 `FocusGuard` 让位给文本编辑，不抢输入框的复制粘贴。
   `Ctrl+D` 原位级联复制保留。

腿 `UiGuardsTest::runtimeDesignerHasOfficialDragAndClipboard`（18 passed）锁住三条结构性事实：
控件库 `dragEnabled + DragOnly`、画布 `acceptDrops()`、两个快捷键都在。

### B1f 已落地（2026-11-09）：属性/列/图层编辑撤销的真实修复

> 对 B1c「属性编辑进撤销栈：600ms 防抖合并」的就地更正（原文保留）：合并机制存在，
> 但撤销点存的是「改后」状态（写时复制两层只处理了第一层），实际撤不掉这次编辑。

- **真因**：`pushUndo()` 的快照与当前布局共享 `pages`；即使 detach 了 `pages`，页里的
  `controls` 仍是共享数组。属性编辑、列编辑、图层调整都在 pushUndo **之前**抓到裸
  `RuntimeControl*` / 页指针，之后经该指针写回不经过 QList 访问器、不触发 detach ⇒
  写回同时改到快照，撤销只能撤到「已改」状态。
- **修法**：`pushUndo()` 里 `pages.detach()` 之后逐页 `controls.detach()`，快照两层都
  自持；`m_layout` 原地址不变，预先抓到的页/控件指针与画布指针都不失效。
- **腿**：`designerPropertyEditUndoRestoresValue`——画布加控件→选中→真实标题输入框改值：

### B2-3e 已落地（2026-11-09）：Tab页（页级内层 Tab）

官方 9.3：「Tab页控件可理解为多个组合框控件的组合，一个组合框对应一个 Tab页。」

**实现方式与官方不同，这里说明原因**：官方把它做成可拖放的**容器控件**，子控件要指向
「我属于哪个容器」。那样一旦删除/重排容器，子控件就成了悬空引用——要么静默删掉用户的控件，
要么位置突变，两种都不可接受。所以改成**页级**内层 Tab：

- 页持有 `innerTabNames / innerTabHeight / defaultInnerTab`；控件只记 `innerTab`（-1 = 不在 Tab 内）。
  **没有父引用，就不可能悬空**；标签变少时越界归属在加载阶段退回 -1（画布），退化行为可定义。
- 控件库「布局」组仍有「**Tab页**」条目（与官方分组一致），拖入 = 给当前页启用内层 Tab
  （弹框填标签名，逗号分隔，清空 = 关闭）。
- 设计器：画布区顶部画标签条（当前标签高亮），下方标注「Tab 内容区」；
  `toCanvasRect/toStoredRect` 对 `innerTab >= 0` 的控件做**标签条高度偏移**（显示下移、写回减回）。
- 运行视图：`buildInnerTabBar` 在内容区顶部建可切换标签条；`applyInnerTabVisibility`
  只对**当前页**控件按 `innerTab` 显隐；`controlGeometry` 的画布区顶部让出标签条高度。
- 腿：`innerTabsRoundTripAndClampOrphans`（三项往返 + 越界退回 -1）、
  `innerTabStripOffsetsDesignerAndRuntime`（设计器偏移互逆 + 运行视图 1:1 时 y=40）；
  `UiGuardsTest` **36 passed**。

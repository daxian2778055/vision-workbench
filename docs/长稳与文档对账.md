# 长稳与文档对账

两件事都是"防劣化"：**长稳**防运行期越跑越差，**文档对账**防文档与代码渐行渐远（本仓已因此踩过 4 次）。

---

## 一、长稳（soak）

### 1. 短跑：每次门禁都跑（CI 口径）

用例 `soak_test`：连续模式跑**真实链路**（读盘 → HALCON 读图 → 形态学 → Blob分析 → 公式计算 → 条件计数 → 延时），
逐秒采样轮次 / 失败轮次 / 进程句柄数 / 工作集。

- 时长：环境变量 `VFP_SOAK_SECONDS`（ctest 内置 20 秒）
- 判定：轮次 ≥ 10、失败轮次 = 0、句柄增长 ≤ 500、工作集增长 ≤ 300 MB
  （**预热后**起算——首轮要懒初始化，实测首轮读图 ~1.9s，不排除预热会把"启动期分配"误判成泄漏）
- **实测基线（本仓 25 秒）**：2313 轮 / **92.5 轮每秒** / 0 失败轮次 / 句柄 Δ1 / 工作集 Δ0 MB

### 2. 长跑：现场 72 小时

```powershell
powershell -ExecutionPolicy Bypass -File tools\soak.ps1 -Hours 72        # 默认 72；可用 -Hours 0.5 试跑
```

- 进度文件逐秒追加（`logs\soak_progress.txt`），另开终端观察：`Get-Content logs\soak_progress.txt -Wait`
- 报告（`logs\soak_report_<时间戳>.txt`）含**逐秒序列**与逐节点统计（执行次数 / 失败 / 最大耗时），
  "预热一次性分配"还是"持续线性增长"全靠这份序列判断——长跑复盘用的也是同一份数据
- 判据同短跑；退出码非零 = 有失败轮次或增长超限

### 3. 长跑怎么看（经验口径）

| 现象 | 通常含义 |
|---|---|
| 轮次/秒随时间下降 | 节拍漂移：先看报告里各节点 `maxMs` 是否变大，再看磁盘/外设/相机是否变慢 |
| 句柄持续**线性**增长 | 句柄泄漏：优先查相机、通信、文件句柄是否未释放 |
| 工作集阶梯式上涨后持平 | 正常（缓存/内存池）；**持续线性上涨**才是泄漏 |
| 出现失败轮次 | 用报告的逐节点 `failures` 定位到具体算子 |

## 二、文档对账（doc_check）

```powershell
powershell -ExecutionPolicy Bypass -File tools\doc_check.ps1
```

机械核查两类**可验证**的声明（不做语义猜测），有问题即以非零码退出：

- **A**：文档里声称"已交付 / 已存在"的节点类名，必须在 `src/NodeRegistry.cpp` 里有 `VFP_REG`。
  带"移除 / 禁用 / 删除 / 关闭 / 不做 / ❌"等否定词的行会跳过（避免把"已下线"误报成缺失）；
  基类与"设备管理路径"节点（如通信节点由 `CommunicationManager` 按设备配置实例化）在**豁免表**中并写明理由。
- **B**：文档中以反引号标注的仓库相对路径必须存在（按 仓库根 / src / include / tests / tools / docs **多根**解析，
  避免把"没写目录前缀"误报成"文件不存在"）。

**首次运行实测**：26 个文档、43 条声明、115 条路径引用 → 修掉脚本假阳性后剩 **1 条真发现**
（`documentation-summary.md` 索引了一个不存在的《深度学习集成指南》）→ 补齐该文档后归零。

### 为什么需要它

路线图里出现过 **4 条**"文档说缺、代码其实已有"（检测 / 角度面积 / 相机 IO / 标准件比对），
人工核对挡不住，而这类错误会直接导致**重复开发或错误排期**。所以把核对写成脚本并纳入门禁：
文档与代码一旦对不上，门禁先红。

> **2026-09-14 代码审查结论**：执行引擎存在 6 项影响检测正确性与稳定性的缺陷（参数引用漂移、跨轮数据串扰、多流程状态串扰、延时崩溃路径、循环/分支语义缺陷、固定 50ms 限速）。**在修复并补真实集成测试之前，不宜宣称达到 VM 4.4 工业交付水平。**

### 阶段一：补齐可用（建议 1–2 个月）

**目标**：能独立交付"定位 + 测量 + 识别 + 基础检测"的完整项目。

1. **按 OpenCV 补齐被禁用算子的等价能力**（G-P0-6）：角度用两条拟合线夹角、面积用 OpencvBlobNode 面积端口等 OpenCV 实现，验证精度后注册；**勿直接恢复已禁用的 HALCON `AngleMeasure`/`Area` 注册**（违反 `VisionIntegrationPolicy`）。此步投入最小、收益直接。
2. **深度学习检测能力**（G-P0-1）：新增 `DnnDetectNode`（ONNX YOLO），覆盖"缺陷定位"这一最高频场景。
3. **IO 与光源控制**（G-P0-4 / G-P0-5）：先做 Modbus 线圈映射版 IO + 串口光源控制器，快速具备"控制外设"能力。
4. **长稳验证**（G-P1-9）：建立 72h 连续运行测试，守住 7×24 底线。

> 阶段一结束时，可在**端到端集成测试通过**的前提下，宣称覆盖 VM 4.4 四大场景中的"定位/测量/识别"三项，检测具备基础能力。若执行引擎正确性（§3.21）尚未修复，则仍不宜宣称达到工业交付水平。

### 阶段二：补齐工业互联与深度学习全栈（建议 3–5 个月）

1. **OPC UA**（G-P0-3）与 **S7 原生**（G-P1-4）——打开汽车/半导体/3C 高端客户。
2. **分割 + 异常检测 + 训练工具**（G-P0-2 / G-P1-2 / G-P1-3）——深度学习对标 VM 4.4 完整矩阵。
3. **对外 SDK + 算子插件**（G-P1-7 / G-P1-8）——形成开放生态，这是相对 VM 4.4 的差异化优势。
4. **标准件比对**（G-P1-1，✅ 已交付：黄金差影 + 对齐 + 边缘抑制）与**国际化**（G-P1-5，v1 已交付机制 + 主干翻译；硬编码字面量覆盖待补）。

> 阶段二结束时，深度学习与工业通讯基本对齐 VM 4.4，且开放性更强。

### 阶段三：拉开差距（6 个月以上）

1. **3D 视觉**（G-P2-1）：点云接入 → 预处理 → 3D 匹配 → 3D 测量。（**范围待定**：VM3D 为独立平台，需先论证 3D 是否纳入 VM 4.4 对标。）
2. **子流程/分组**（G-P1-6）：支撑超大规模流程工程化。
3. **方案模板与行业方案包**（G-P2-5）：从"工具"走向"解决方案"。
4. **推理加速**（G-P2-4）：GPU 后端 + 批处理，追赶 VM 4.4 宣称的效率优化。

## 6. 验收方式

每个差距项建议按以下四步闭环：

1. **需求落位**：在《需求规格说明书》中对应 FR/NFR 编号（本文已标注）；
2. **实现 + 单测**：新增算子需补充序列化测试与自检（对齐 `tests/opencv_serialization_test.cpp` 模式）；
3. **场景验证**：用真实样本跑通 AC 系列验收标准（见 SRS 第 7 章）；
4. **文档同步**：更新《用户操作手册》与算子帮助（F1）。

> **测试纪律提醒**：当前 Release 构建 5 个 CTest 通过，但 `integration_test.cpp` 未真正执行连接后的端到端流程，不能覆盖 E1–E6。差距项验收前须先补齐：连续运行多轮参数引用、条件分支汇合空值传播、循环+分支、双流程触发隔离、延时安全停止等真实集成测试。

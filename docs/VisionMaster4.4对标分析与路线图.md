## 1. 总览：能力对照雷达

| 能力域 | VisionMaster 4.4 | 本平台现状 | 差距 | 权重 |
|--------|------------------|-----------|------|------|
| 图形化流程编辑 | 成熟，千余算子 | 完整（拖拽/连线/撤销/多标签/搜索/调试） | **小** | 高 |
| 定位 | 模板匹配、特征匹配、多目标 | 模板匹配+拟合+Blob+角点，**缺特征匹配** | 中 | 高 |
| 测量 | 卡尺、距离、角度；3D 平整度/段差/间隙 | 卡尺+距离+圆测量，**缺 3D 测量** | 中 | 高 |
| 识别 | 一维码/二维码/DL OCR | 一维码+二维码+传统 OCR+DeepOCR | **小** | 高 |
| 检测 | 表面缺陷、轮廓缺陷、标准件比对 | 表面缺陷基础可用，**缺标准件比对** | 中 | 高 |
| 深度学习 | 分类/检测/分割/异常检测/字符/检索/训练工具 | **仅分类+OCR** | **大** | 高 |
| 资源管理 | 相机、IO、光源 | 相机完整，**缺 IO 板卡与光源控制** | **大** | 中 |
| 通讯 | 丰富工业协议 | TCP/串口/Modbus/PLC，**缺 OPC UA、S7 原生** | 中 | 高 |
| 3D | 预处理/轮廓匹配/特征提取/拼接 | 无 | **大** | 中 |
| 运行界面 | 自定义运行界面 | 已有设计器 | **小** | 中 |
| 开放性 | 图形化 + SDK + 算子设计模式 | 图形化 + 脚本，**缺 SDK 与算子插件** | 中 | 中 |
| 平台服务 | 权限/日志/报表/国际化 | 权限/日志完备，国际化偏弱 | 中 | 低 |

**结论**：功能骨架在"流程编辑 + 识别"上已可用，但**执行引擎正确性（参数引用、跨轮数据、流程隔离、安全停止、循环/分支）尚未达到工业级**，须先修复（见《需求规格说明书》§3.21）；补齐后，深度学习、3D、IO/光源、工业通讯（OPC UA/S7）是四个主要能力缺口。注意：本表与全文中的 ✅ 表示"功能存在"，不等同于已通过端到端工业场景验收。

## 2. 优势（应当保持并放大）

| 优势 | 说明 |
|------|------|
| **算法自主可控** | 采用 `VisionIntegrationPolicy`：日常算法走 OpenCV，HALCON 仅保留 DeepOCR，降低商业库依赖与授权风险 |
| **脚本扩展 + 安全沙箱** | ScriptNode 支持 Python/Lua，配套 `ScriptSecurityPolicy`（语言白名单、隔离、环境清理、超时、审计、总开关）——VM 4.4 无对等安全粒度 |
| **多相机与共享机制** | GlobalCameraManager 支持多相机命名、多设备绑定、冲突检测、多算子共享同一相机（注：节点运行状态当前仍走全局 `s_currentInstance`，双流程下存在状态串扰，需在执行器上下文隔离后才会稳定，见 §3.21 E3） |
| **通讯矩阵较全** | TCP(客户端/服务器)、串口、Modbus TCP/RTU(主站/从站)、PLC 多品牌，含寄存器表、字节序、心跳、监视器 |
| **运行界面设计器** | RuntimeInterfaceDesigner 可对标 VM 4.4 运行态界面 |
| **工程化基础** | 撤销快照、拓扑排序环检测、性能面板、输出查看器、CTest 测试、环境自检、算子自检 |

## 4. 落地路线图

### 阶段一：补齐可用（建议 1–2 个月）

**目标**：能独立交付"定位 + 测量 + 识别 + 基础检测"的完整项目。

1. **按 OpenCV 补齐被禁用算子的等价能力**（G-P0-6）：角度用两条拟合线夹角、面积用 OpencvBlobNode 面积端口等 OpenCV 实现，验证精度后注册；**勿直接恢复已禁用的 HALCON `AngleMeasure`/`Area` 注册**（违反 `VisionIntegrationPolicy`）。此步投入最小、收益直接。
2. **深度学习检测能力**（G-P0-1）：新增 `DnnDetectNode`（ONNX YOLO），覆盖"缺陷定位"这一最高频场景。
3. **IO 与光源控制**（G-P0-4 / G-P0-5）：先做 Modbus 线圈映射版 IO + 串口光源控制器，快速具备"控制外设"能力。
4. **长稳验证**（G-P1-9）：建立 72h 连续运行测试，守住 7×24 底线。

> 阶段一结束时，可在**端到端集成测试通过**的前提下，宣称覆盖 VM 4.4 四大场景中的"定位/测量/识别"三项，检测具备基础能力。若执行引擎正确性（§3.21）尚未修复，则仍不宜宣称达到工业交付水平。

### 阶段二：补齐工业互联与深度学习全栈（建议 3–5 个月）

1. **OPC UA**（G-P0-3）与 **S7 原生**（G-P1-4）——打开汽车/半导体/3C 高端客户。
2. **分割 + 异常检测 + 训练工具**（G-P0-2 / G-P1-2 / G-P1-3）——深度学习对标 VM 4.4 完整矩阵。
3. **对外 SDK + 算子插件**（G-P1-7 / G-P1-8）——形成开放生态，这是相对 VM 4.4 的差异化优势。
4. **标准件比对**（G-P1-1）与**完整国际化**（G-P1-5）。

> 阶段二结束时，深度学习与工业通讯基本对齐 VM 4.4，且开放性更强。

### 阶段三：拉开差距（6 个月以上）

1. **3D 视觉**（G-P2-1）：点云接入 → 预处理 → 3D 匹配 → 3D 测量。（**范围待定**：VM3D 为独立平台，需先论证 3D 是否纳入 VM 4.4 对标。）
2. **子流程/分组**（G-P1-6）：支撑超大规模流程工程化。
3. **方案模板与行业方案包**（G-P2-5）：从"工具"走向"解决方案"。
4. **推理加速**（G-P2-4）：GPU 后端 + 批处理，追赶 VM 4.4 宣称的效率优化。

## 6. 验收方式

每个差距项建议按以下四步闭环：

1. **需求落位**：在《需求规格说明书》中对应 FR/NFR 编号（本文已标注）；
2. **实现 + 单测**：新增算子需补充序列化测试与自检（对齐 `tests/opencv_serialization_test.cpp` 模式）；
3. **场景验证**：用真实样本跑通 AC 系列验收标准（见 SRS 第 7 章）；
4. **文档同步**：更新《用户操作手册》与算子帮助（F1）。

> **测试纪律提醒**：当前 Release 构建 5 个 CTest 通过，但 `integration_test.cpp` 未真正执行连接后的端到端流程，不能覆盖 E1–E6。差距项验收前须先补齐：连续运行多轮参数引用、条件分支汇合空值传播、循环+分支、双流程触发隔离、延时安全停止等真实集成测试。

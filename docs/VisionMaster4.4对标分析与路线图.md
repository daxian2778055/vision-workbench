## 4. 落地路线图

### 阶段一：补齐可用（建议 1–2 个月）

**目标**：能独立交付"定位 + 测量 + 识别 + 基础检测"的完整项目。

1. **按 OpenCV 补齐被禁用算子的等价能力**（G-P0-6）：角度用两条拟合线夹角、面积用 OpencvBlobNode 面积端口等 OpenCV 实现，验证精度后注册；**勿直接恢复已禁用的 HALCON `AngleMeasure`/`Area` 注册**（违反 `VisionIntegrationPolicy`）。此步投入最小、收益直接。

> 阶段一结束时，可在**端到端集成测试通过**的前提下，宣称覆盖 VM 4.4 四大场景中的"定位/测量/识别"三项，检测具备基础能力。若执行引擎正确性（§3.21）尚未修复，则仍不宜宣称达到工业交付水平。

## 6. 验收方式

每个差距项建议按以下四步闭环：

1. **需求落位**：在《需求规格说明书》中对应 FR/NFR 编号（本文已标注）；
2. **实现 + 单测**：新增算子需补充序列化测试与自检（对齐 `tests/opencv_serialization_test.cpp` 模式）；
3. **场景验证**：用真实样本跑通 AC 系列验收标准（见 SRS 第 7 章）；
4. **文档同步**：更新《用户操作手册》与算子帮助（F1）。

> **测试纪律提醒（2026-09-24 更新，2026-09-25 复跑并补第 ③ 条）**：原文"当前 Release 构建 5 个 CTest 通过、`integration_test.cpp` 未真正执行连接后的端到端流程、不能覆盖 E1–E6，须先补齐五类真实集成测试"**已过期**——该文件现有 **43 个测试函数**，当年点名的五类（连续多轮参数引用、分支汇合清空、循环+分支、双流程触发隔离、延时安全停止）**都已存在并真跑真断言**；全量门禁为 **2026-09-25 全量重编后复跑，Release 下 28 个 CTest 套件全部通过**（较上一轮 +1，新增的是遍历注册表的全节点 `execute()` 冒烟 `NodeExecuteSmokeTest`；`tools/ci.ps1`）。同日第三轮审核后再复跑仍为 **28/28、88.23 s**，但**机制已变**：28 条 `add_test` 全部改经 `vfp_add_qtest()` 包装（cmake 跑 `-o <file>,txt` 并回读转发），因此"直接跑测试 exe 看 stdout"从此不再是有效复现手段，明细一律看 `ctest` 输出或 `build/Testing/*.txt`。
> 但这条提醒要防的问题一个都没消失，只是换成了三条，长期有效：
> ① **门禁绿 ≠ 现场验收**——上述用例全部跑在合成图像与内存流程上；AC1–AC8 需要真机与真实样本，《需求规格说明书》§7 实测记录目前为 **0 条**。
> ② **默认 `QSKIP` 的用例不得算作"已验证"**——受限令牌 / AppContainer 遏制、低完整性隔离等在默认门禁里是跳过状态（跳过理由写在代码注释里，这是有意的：跨会话结果不确定时宁可跳过，也不制造假绿）。新增验收口径时，必须同时写明"在什么开关下才真跑"。
> ③ **遍历式门禁必须自证能变红**——凡"扫一遍注册表/配置/目录再断言"的用例，覆盖面为 0 时也会全绿。本轮先写的临时诊断程序（`tests/node_smoke_diag.cpp`，取完数据后已删除）就出现过：独立测试进程没调 `registerAllNodes()`，注册表为空，循环一次不跑，结果 **`pass=0 fail=0` 仍显示 Passed**。正式用例 `NodeExecuteSmokeTest` 据此固定带两道保险——规模断言（`registryIsNotEmpty` 断言注册数 > 60；② 为 `checked >= 40`，① 已改为"注册表直算 `eligible` + `executed == eligible` 精确等式"，见下方 ③-b）+ 一次**故意把被测契约改坏再重跑**确认 `***Failed`（本次是把成功默认值改回 `false`）。给门禁写"通过"结论之前，先回答"它能不能变红、我验证过没有"。
> **2026-09-25 第二次追加（同一纪律的两个新教训）**：③-a **软下限断言的书写顺序会掩盖真实命中**——`QVERIFY2(checked >= N)` 一旦失败即中断该测试函数，同函数里已经命中的缺陷（本轮是 `ImageSubNode`/`ImageDivNode` 的"成功且零产出"）就不会打印，看起来像"覆盖面数字写错了"，实际把结论挡住了。规则：**实质结论一律排在覆盖面之前**。③-b **覆盖面不要用 `>= N` 自证**，改为"`eligible` 由注册表直算 + 断言 `executed == eligible` 精确等式"，并再加一条**排除表与注册表的自洽断言**（`skipListsMatchRegistry`：跳过清单里的 id 必须仍在注册表内）——否则算子改名/注销只会让覆盖面静默缩水，门禁反而"更绿"。该断言本身也已用假 id 负向自证为红后再删除。
> **2026-09-25 第三次追加（第三轮审核换来的两条，同样长期有效）**：③-c **变红了还要看得见——"能变红"不等于"可定位"**。本轮之前 `ctest` 下 28 个套件的 QtTest 明细**一行都看不到**（链接 `vfp_core` 的测试 exe 会整个丢掉 stdout，PE 子系统实测是 console 而非 GUI，根因未定位），也就是说 ③ 所要求的"故意改坏再重跑确认变红"只能靠手工 `-o <file>,txt` 落盘才成立，别人按 `ctest` 复现不到我们写进文档的任何 `FAIL!` 行。规则：**遍历式门禁必须同时证明"红的时候能打印出为什么红"**，做法是 `vfp_add_qtest()`（`tools/run_qtest.cmake`）用 cmake 自己的 stdout 转发 QtTest 结果文件；且**结果里没有 `Totals:` 行就直接判失败**——"崩溃/没跑完/输出为空"绝不能显示成一条安静的 PASS。③-d **数字口径必须落成可执行定义，文档只引脚本输出**。同一句静态扫描描述，两位复核者各自复算出 44/12/41 与 44/22/13、44/47/20，全部"对自己的正则正确"，因为没有一条定义写在能跑的地方。规则：任何要进文档的统计口径都要有一个 `tools/` 下的脚本与之对应（本轮是 `tools/scan_silent_green_paths.py`），文档里的数字改不动脚本就等于没更正；脚本只报告、exit 恒 0，**不把源码形状计数挂成 CI 门禁**（那只会冻结数字，不会修代码）。

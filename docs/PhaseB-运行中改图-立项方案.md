## 1. 目标与非目标

**目标**：运行中允许编辑拓扑；**当轮不受影响**（跑完自己的快照），**下一轮生效**；被删节点不崩、不泄漏。

**非目标（范围外，避免误解）**：
- 不追求"热替换正在执行中的那个节点"（当轮语义就是跑旧图）；
- 不改参数编辑现状（已支持）；
- 不做跨流程的事务性发布（多流程各自独立，沿用现有隔离）；
- 不引入新的编辑锁类型（只做"减法 + 语义明确"）。

## 2. 已交付地基（可直接复用）

| 能力 | 出处 |
|---|---|

| 删除走墓碑 + 延迟释放（快照释放后才真删） | `GraphSnapshotGuard` / `releaseGraphSnapshot`；用例 `testGraphSnapshotDefersDeletionDuringRound` |
| **改图即置脏、下一轮懒重建索引** | `FlowScene::nodeAdded/nodeRemoved/connectionAdded/connectionRemoved` → `FlowExecutor::markGraphStructureDirty`（4 条连接，已核实） |

| 三类缓存的现状判定与 5 条前置条件清单 | `ee08f41`（写在 `onSceneNodeRemoved` 注释内） |

## 3. 剩余工作（分期）

### Stage 1 — 锁纪律（前置条件；**无用户可见变化**）

按 `ee08f41` 的 5 条清单执行：

1. `m_nodeData` / `m_validOutputs` / `m_nodeOutputVars` 的**全部访问（约 20 处）**统一入 `m_graphCacheMutex`；
2. 锁序固定 `graphCacheMutex → m_mutex`（现状即此序：`setFlowScene` / `invalidateDownstreamOf`），**禁止反向**；
3. 嵌套收口：`executeNode` 会调 `propagateData` / `collectNodeOutputVars` —— 二选一（**推荐把锁收口到最外层函数**，可用静态检查；备选 `QRecursiveMutex`，本仓 MvsImageSourceNode 有先例）；
4. `onSceneNodeRemoved` 恢复"删节点即清三类缓存 + `m_validOutputs.remove`"；
5. `invalidateDownstreamOf` 的"查状态 → 清缓存"**窄窗口**一并收进外层锁（本轮读码发现，当前后果有限）。

**验收**：全量门禁绿 + 并发压测 N 轮无失败 + **代码检索确认三类缓存无锁外访问**（可用 CI 侧脚本或人工清单）。
**必做反证**：故意抽掉一处锁 → 并发用例必须失败（沿用本项目"不空转"的口径）。

### Stage 2 — 发布语义与回收（用户可见）

- **版本边界定义**：以**轮次边界**为发布点（复用现有快照机制），并在文档/UI 明示"改动下一轮生效"；
- **缓存回收**：轮首剪枝（现有）+ 界面侧即时清理（Stage 1 后安全）；
- **用例**：运行中①删节点 ②改连线 ③加节点 各一条 —— 断言"当轮不受影响、下一轮生效、无崩溃、无泄漏"。

### Stage 3 — 放开编辑锁 + UX/文档

- 编辑锁判据改为"仅对确实不安全的操作禁止"（逐项确认，不做一刀切）；
- UI 提示"该改动将在下一轮生效"+ 提供取消路径；
- 文档：运行中改图的语义与边界（含**什么时候仍必须停机**）。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 锁纪律改动引入死锁/性能退化（引擎核心） | 锁序固定 + 收口到最外层 + 压测 + 静态检索 + 每阶段独立提交可回退 |
| 语义被误用（用户以为当轮就生效） | UI 明示 + 文档 + 版本边界写进验收 |
| 半改造成"假安全" | 明确禁止：不做"部分加锁"，Stage 1 一次做完 |

## 5. 验证与验收

- **可自动验证**：Stage 1 全部（加锁 + 反证 + 压测）、Stage 2 的三条用例；
- **只能真机/人工**：长时间连续运行下的手感与稳定性；与设备联动的现场场景。

## 6. 决策点（需拍板）

- **D1**：现场是否确认"运行中改拓扑"是刚需？
  - 是 → 三阶段全做；
  - 否 → 只做 Stage 1（作为**防御性锁纪律**，为将来留出安全边界）+ 保留现有"暂停中可改图"，Stage 2/3 不做。
- **D2**：版本粒度取"轮次边界"（改动自动在下轮生效）还是"手动应用"按钮（用户显式发布）？
- **D3**：是否需要"运行中改图"的审计日志（现场追溯谁在什么时候改了什么）？

## 7. 明确不做（本立项范围外）

- 编辑期不引入"锁场景"的新机制；
- 不改 `FlowScene` 的快照/墓碑实现（已满足需求）；
- 不碰通信/持久化路径。

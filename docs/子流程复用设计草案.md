# 子流程复用设计草案（FR15.10 运行期调用）

> **状态：v1 已交付（2026-09-24）**，按第 2 节**方案 B**（方案内命名子图）落地。
> 交付内容与 v1 取舍见文末「8. v1 交付说明」；本文其余章节保留为原始设计记录。

## 1. 现状与边界（先说清"已有什么、缺什么"）

| 能力 | 状态 | 实现/说明 |
|------|------|-----------|
| 单算子复用 | ✅ | `FlowScene::duplicateNode`（同流程内复制）、`NodeTemplateStore`（跨方案/跨会话的单算子模板） |
| **子图复用（设计期）** | ✅ 2026-09-23 | `FlowSnippet`：选中多算子 → 复制/粘贴（含**内部连线**）、片段文件 `.vfseg` 导入导出；16 条用例 |
| **子流程调用（运行期）** | ❌ 未做 | 把一段流程当**一个算子**调用——"调同一个"而不是"拷一份" |

**为什么片段不能冒充子流程**：片段是**值拷贝**（改源不会同步到已粘贴处），且不解决"参数进、结果出如何映射"。
运行期子流程的真正价值是：**一处修改、所有引用它的方案同步生效**，并且画布不被重复段淹没。

## 2. 语义选项（需产品决策，代价差异很大）

| 方案 | 语义 | 优点 | 代价 |
|------|------|------|------|
| **A. 跨方案引用** | 子流程节点指向另一个 `.vfp` 里的某个流程 | 复用度最高（一套库多用） | 方案**不再自包含**：被引用文件丢失/改名/改逻辑，引用方行为随之变化；换机要带一套文件 |
| **B. 方案内命名子图** | 同一方案内给一段流程起名，作为"函数"调用 | 自包含、离线友好、迁移零成本 | 只能在本方案内复用；画布需要"子图定义"的表达方式 |
| **C. 导出为只读算子** | 子流程编译成独立文件（近似插件） | 引用方完全解耦、可加密 | 需要额外工具链与版本管理，超出本轮语境 |

**建议：先做 B**（自包含、风险可控），A 作为后续面向"企业库"的扩展。
理由：本平台部署形态是"整目录拷贝 + 离线运行"（见 `docs/离线可用性说明.md`），A 的"外部文件依赖"会直接冲击这个前提。

## 3. 数据结构（草案，方案 B）

子流程定义放在**场景 extras**（与分组同源 ⇒ 随方案保存，且天然被撤销快照带上）：

```json
"subFlows": [
  { "name": "预处理",
    "inputs":  [ { "name": "图像", "port": "数据输入" } ],
    "outputs": [ { "name": "结果", "port": "数据输出" } ],
    "nodes": [...], "connections": [...],
    "groups": [...] }
]
```

调用点是一个新算子 `SubFlowNode`（普通算子，走注册表 ⇒ 自动获得参数面板/序列化/自检）：

| 参数 | 含义 |
|------|------|
| `subFlowName` | 下拉选择，选项来自当前场景的 `subFlows` |
| 输入映射 | 每个子流程输入 → 调用点的输入端口（上游连线）或全局变量 |
| 输出映射 | 每个子流程输出 → 调用点的输出端口 |

## 4. 执行引擎要点（真正的难点，逐条给验收口径）

1. **嵌套执行**：本仓是"一个流程一个执行器"（多流程并发）。子流程调用建议**同线程内联**执行
   （复用当前执行器与轮次，不新建线程/执行器）——否则会与相机、通信资源以及"每流程独立执行器"
   的既有约束打架。
2. **变量作用域（最大风险点）**：`{模块号.参数名}` 的解析是基于**全局**的 `m_nodeOutputVars`（按模块号索引）。
   若子图里同一算子被两个父流程同时调用，输出会互相覆盖。**必须先解决命名空间**，
   建议键改为 `{子流程实例号.模块号.参数名}`，并保留旧键作为兼容回退。
3. **参数与结果映射**：映射缺失必须**显式失败**（报"子流程输入 X 未映射"），不能静默传空。
4. **递归保护**：A 调 B、B 调 A（或自调）→ 深度上限 + 明确报错。
5. **失败语义**：子图内节点失败时，按调用点所在流程的 `stopOnFailure` 收口，并把**具体哪个子节点失败**
   写进日志与结果表（否则现场只看到"子流程失败"，无从排查）。
6. **统计口径**：轮次记录（良率/NG 按节点分布，见 `docs/统计报表说明.md`）必须包含子图内节点，
   否则统计会漏掉一整段。

## 5. 分阶段建议（每阶段可单独验收）

| 阶段 | 内容 | 验收 |
|------|------|------|
| 1 | 数据结构 + 编辑（定义子图、调用节点、映射界面），**不执行** | 方案存得下、看得见、往返一致 |
| 2 | 同线程内联执行 + 变量命名空间 | 两个流程各调一次同一子流程，互不影响 |
| 3 | 递归保护 / 失败语义 / 统计口径 / 用例 | 见下"验收口径" |

## 6. 验收口径（写在这里，免得事后扯皮）

- 同一方案内两个流程各调用同一子流程一次：两次执行结果互不污染（命名空间回归）；
- 子流程定义被删/改名后，引用它的调用点**加载时可见地降级或报错**（不得静默跑旧逻辑）；
- 递归调用被拒绝，且给出清晰原因；
- 子流程内节点失败时，结果表能指出**具体是哪个子节点**失败；
- 子流程内的算子执行计入轮次统计（否则良率虚高）。

## 7. v1 交付说明（2026-09-24）

**落地形态**（与第 3 节草案的差异见「取舍」）：

| 组件 | 实现 |
|------|------|
| 定义存储 | `FlowScene` extras 的 `subFlows` 数组（`include/SubFlowDefs.h`）：`{name, members[], input, output}`，成员用**模块号**（与分组同约定），随方案保存/加载并被撤销快照带上 |
| 定义入口 | 编辑菜单「定义为子流程…」（选中 ≥2 算子弹名框）；「删除子流程定义…」按名删除（画布算子保留） |
| 调用点 | 注册算子 `SubFlowNode`（"逻辑与控制"分类，参数 `subFlowName`） |
| 执行 | `FlowExecutor::executeSubFlow` **同线程内联**：复用循环体 P3 模式（轮首 `collectSubFlowBodies` 收集成员 → 主遍历跳过 → 调用点执行时按缓存拓扑序逐个 `executeNode(member, false)`） |

**边界与数据流（v1 单进单出，定义时自动推导）**：

- 入口 = 成员中唯一"无来自成员内部入边"的算子；出口 = 唯一"无去向成员内部出边"的算子；不满足（0/≥2）定义被拒绝；
- 成员与成员之外的算子**不允许连线**（定义时校验拒绝），数据一律经调用点进出：入口吃调用点输入端口 0、出口结果回写调用点输出端口 0（与普通算子同一出口路径，下游无感知）。

**验收口径对照（全部有测试钉住，`tests/subflow_test.cpp` 8 用例）**：

| 口径 | 落地 |
|------|------|
| 两次调用互不污染 | 内联顺序执行 + 成员与主图无连线 ⇒ 两个调用点各喂各的输入、各取各的输出（`testTwoCallersIsolation`：callerA=11 / callerB=22） |
| 定义缺失可见报错 | 调用点执行时报「子流程「X」未定义（可能已被删除或改名，或名字写错）」，调用点按失败收口（`testUndefinedRejected`）；成员被删则报「定义损坏」 |
| 递归拒绝 | 调用栈查重 + 深度上限 8，报「检测到子流程递归调用：A→B→「A」，已拒绝」（`testRecursionRejected`） |
| 具体哪个子节点失败 | 失败成员自身 `nodeExecuted(false)`（结果面板标红）+ `executionError` 带成员 fullName（"子流程「X」的算子「Y」执行失败"） |
| 成员计入统计 | 成员走同一 `executeNode` ⇒ 节点执行次数/耗时/失败与轮次统计天然包含（与循环体同口径） |

**v1 取舍（相对草案的简化，后续按需升级）**：

1. **跨边界 `{成员模块号.参数名}` 文本引用不支持**——草案第 4.2 条的"实例号命名空间"是为支持它设计的；v1 用"成员与外部无连线"的边界约束让该问题不存在，主图下游请走调用点的输出端口或 `{调用点模块号.参数名}`。全局 `m_nodeOutputVars` 中成员变量仍按"最近一次调用"覆盖，但**子流程内部引用都在本次调用的成员执行之间发生**，语义正确。
2. **成员不得与循环体交叉**——轮首收集时让位给循环体，若因此丢了入口/出口，执行时报"定义损坏"。
3. **成员是画布真实算子**（不是草案第 3 节的"定义内嵌 nodes/connections 副本"）——"一处修改、所有引用同步生效"天然成立，且撤销/序列化零新增机制；代价是子流程成员占画布（建议配合分组框折叠使用）。
4. `SubFlowNode` 的 `subFlowName` 是文本参数（非下拉）——写错执行时可见报错；做下拉需节点反查场景，留待后续。

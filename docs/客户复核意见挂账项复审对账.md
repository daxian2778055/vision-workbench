## 2. 分族实测要点

### 2.1 P0 族（写闸与登录门控）

- 闸位对照：报告基线的主窗闸位为五处调用；当前为七处调用位（另有注释提及一处不计入），新增位含**单算子执行**与**下游重算**两处。
- 闸语义当前口径：运行闸 = 已登录 且 写闸未开。写闸开启时（出厂口令仍在用或用户表读不到）**不受理新一次运行发起**；已在跑的流程不被打断（产线不停线口径）。
- 出厂口令闸为失败关闭：只有明确读到「出厂口令已停用」才放开；读不到用户表按未停用处理并给出可读原因。
- 种子账号：仍在（建表路径插入 admin 种子）；因闸语义，种子态下**登录后亦不能跑流与改方案**（改密后闸解，运行自然恢复）。

### 2.2 P1 族（方案信任与网络面）

- 方案包：只读分发标志已落（载入后置只读并阻断覆盖保存）；口令侧与包级加密走既有口令派生 + MAC 口径；**未签名明文方案的包级签名校验未见**（报告此条仍挂账）。
- 路径：方案内相对路径锚定方案目录；目录外绝对路径在载入时须显式确认（未确认即拒载，当前方案保持不变——第二百一十七条把 179 行的「提示·非阻断」升级为「确认·阻断」）；执行侧解析位统一走同一漏斗。
- 通信监听：三类服务端（TCP 监听、UDP 本地绑定、Modbus 从站）绑定面统一走一处解析——**空参＝未配置＝拒启动**（第二百一十九条把 177 行的「留空＝全网卡」默认面撤掉），显式参数须解析为 IP 字面量并原样绑定（确实要全网卡写 0.0.0.0），无效一律拒启动（宁可不起服务，不静默回落扩面）；显式全网卡落日志。
- 第十一轮第三方复核补录两条：P1-6（存活控制块指针的发布/拷贝互斥——第二百三十条收口）与 P2-9（失败加载回滚方案目录快照与只读旗——路径/只读旗/附注三件成功才提交、八条失败支回滚，漏斗与快照位口径不动；第二百三十一条收口）。
- 第十一轮第三方复核 P1-1 残余的工程项补形（U-215）：相对 `..` 形态以往一律按目录内相对计数，解析后落出方案目录者此前不进确认闸——现按解析后落点判界，逃逸与目录外绝对同进确认闸、同权未确认即拒载（行为变更明示：存量含相对逃逸的方案首轮起会先弹确认；第二百三十二条收口）。其余四件属产品选择，逐条点名待拍板：作者签名或 TOFU、编译期 pepper（改则断全部既有 v2 信封兼容）、裸 JSON 策略、applyProjectJson 是否也进确认闸；P1-3 余量（UDP 端口 0 ＋空地址是否也拒 Missing）同类。
- 第十一轮 P1-1 残余四件与 P1-3 余量逐条点名处置（U-216 拍板收束轮，零代码零行为；客户四问回复均为「你决定」＝全量委托技术面处置，执行方按在册口径五处全拍维持）：包级签名与 TOFU 维持不做（回执 1.4 与对账册 O-D 行在册；分享件面的完整性位由 v2 明文打包 HMAC、加密信封口令派生 MAC、旧 v1 明文打包真入口拒收三件收住）；编译期 pepper 维持不加（掺盐即改口令派生，全部既有 v2 信封与既有分享件一起作废，r11 自述「改则断兼容」）；裸 JSON 本机文件维持无完整性位照常载入（回执 1.4 「本机在用文件、不在分享面」句如实记在册）；内存入口 applyProjectJson 维持不进确认闸（无生产调用方，测试面在用；二百一十六条有门禁边界如实登记）；UDP 端口 0 维持「仅发送场景」放行（原注在码在册，一百七十七条「端口零语义不动」）。勘误如实记：第二百三十二条注四「崩溃恢复入口 applyProjectJson 不进闸」句措辞不精确——恢复实走文件载入口（在 U-201 确认闸内被管到），不设闸者只有上述内存入口；附表旧行一字不动，以第二百三十三条为准勘误。P1-3 余量（UDP 端口 0＋空地址是否也拒 Missing）随端口 0 一并维持（二百一十九条的收紧面管端口大于 0 的监听面）。钉位缺口两处（UDP 调用面拒收、内存入口不闸）点名留档，另轮钉族收口。第二百三十三条收口。

### 2.3 P2 族（密码学、守卫、巨型类、仓库卫生、文案）

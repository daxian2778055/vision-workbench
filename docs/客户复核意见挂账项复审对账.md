## 2. 分族实测要点

### 2.1 P0 族（写闸与登录门控）

- 闸位对照：报告基线的主窗闸位为五处调用；当前为七处调用位（另有注释提及一处不计入），新增位含**单算子执行**与**下游重算**两处。
- 闸语义当前口径：运行闸 = 已登录 且 写闸未开。写闸开启时（出厂口令仍在用或用户表读不到）**不受理新一次运行发起**；已在跑的流程不被打断（产线不停线口径）。
- 出厂口令闸为失败关闭：只有明确读到「出厂口令已停用」才放开；读不到用户表按未停用处理并给出可读原因。
- 种子账号：仍在（建表路径插入 admin 种子）；因闸语义，种子态下**登录后亦不能跑流与改方案**（改密后闸解，运行自然恢复）。

### 2.2 P1 族（方案信任与网络面）

- 方案包：只读分发标志已落（载入后置只读并阻断覆盖保存）；口令侧与包级加密走既有口令派生 + MAC 口径；**未签名明文方案的包级签名校验未见**（报告此条仍挂账）。
- 路径：方案内相对路径锚定方案目录；目录外绝对路径在载入时须显式确认（未确认即拒载，当前方案保持不变——第二百一十七条把 179 行的「提示·非阻断」升级为「确认·阻断」）；执行侧解析位统一走同一漏斗。
- 通信监听：三类服务端（TCP 监听、UDP 本地绑定、Modbus 从站）绑定面统一走一处解析——**空参＝未配置＝拒启动**（第二百一十九条把 177 行的「留空＝全网卡」默认面撤掉），显式参数须解析为 IP 字面量并原样绑定（确实要全网卡写 0.0.0.0），无效一律拒启动（宁可不起服务，不静默回落扩面）；显式全网卡落日志。

### 2.3 P2 族（密码学、守卫、巨型类、仓库卫生、文案）

- 密码学：口令侧 PBKDF2 迭代数已按精确值校验；非 memory-hard 属产品选择。
- 守卫：执行器析构两段有界等待（一段 5 秒、二段 15 秒）皆尽才进终局，先过应用层收尾钩子再中止进程；源件注释自指「全砍中止需全核 shared_ptr 化重设计」并指向立项词条。**本项已转立项路线**（五期：测绘与护栏 → 低风险面引用计数化 → 快照与墓碑共享所有权化 → 销毁权收口 → 撤终局中止），其中两处形态抉择须产品拍板。
- 巨型类：主窗体量由报告基线的约四千四百行降至当前约四千三百行（其余为续抽层收束后的余量）；执行器约两千行；三切片处置见 §0。
- 仓库卫生：根目录三枚文本件仍在（两枚自刻墓碑注记、一枚因引用面未断而原地冻结），登记位维持。
- 文案：就地链双语文本表已收进独立面（三十组文本对同序同目标）；完整 tr 普查见 §3。

# 执行器销毁权收口 —— P3 期设计面

> 性质：**设计面**——零代码零行为；P3 期（销毁权收口）的编码前设计，先量后定。
> 触发：客户复核与切片 C 拍板回执（附表第二百零七条）拍定终局撤除语义（中止该执行器并进入可观测终态、进程不中止，硬中止只作不可达兜底）。
> 关系：本件接在 P2 三步之后（P2a 块、P2b 执行器侧、P2c 算子侧已落）；P2d（快照与墓碑共享所有权化）仍另议。
> 依据：HEAD 态逐点实测（创建与销毁全量、触发面持有与调用、子流程残余面、终局护栏现状），面索引见 §7。

## 0. 结论先行

| 项 | 结论 |
|---|---|
| P3 的核心 | 把执行器的**销毁权**从「调用方记得先 join」变成**结构保证**：一个「生命周期令牌」（共享对象，持有者释放最后一个时负责 join 与回收），执行器本体只由令牌拥有 |
| 现状的关键实测 | 销毁**全走 join 路径**（界面侧的回收件与主窗析构的批量回收）⇒ 触发面与子流程残余面**在现状下都因「同线程 + join」而安全**——P3 的价值不是修一个现网缺陷，而是把这份安全从**偶然的线程与时序巧合**变成**结构保证** |
| 终局撤除的可达性 | 撤除硬中止的前提是「析构时线程一定已经退出」——今日靠「两段有界等待 ＋ 失败就中止」兜底；P3 后由令牌保证 ⇒ 中止路径**变为不可达**，可换成「可观测终态 + 现场提示」，硬中止只留作不可达兜底 |
| 期次 | **P3a** 令牌与持有面（令牌 ＋ 触发面绑定持有 ＋ 节点残余面持有）→ **P3b** 销毁权归一（所有销毁路径经令牌释放）→ **P3c** 终局中止撤除（按已拍语义） |
| 判据 | 每步独立轮、行为零变更（末步除外，末步是**明示的行为变更轮**）、红绿臂（红恰破坏腿 ＋ 还原终绿）、座双注册、宿主整轮、附表落笔照用 |

## 1. 销毁权现状（实测）

### 1.1 创建与销毁全量

- 创建：界面侧两处新建执行器（当前执行器位与新建流程位），父对象是主窗。
- 销毁：**全部经回收件**（先停止、再有界等待、再安全回收），主窗析构时对**全部**执行器做同样的批量回收；未发现「直接 delete 执行器」的路径（节点与通信侧的 deleteLater 都与执行器无关）。
- 终局护栏：执行器析构内两段有界等待（一段五秒、二段十五秒，二段前重停一轮），两段皆尽则**中止进程**；正常销毁路径应当在 delete 之前先等待线程退出。

### 1.2 触发面（外部触发起跑）

- 触发管理器按流程名绑定执行器（裸指针），路由在锁内取出指针、**出锁后调用**（请求外部触发与外部触发门控两处）。
- 线程面实测：触发管理器的槽由通信数据到达触发，通信侧的转发可能在采集线程发起，但触发管理器本体在界面线程 ⇒ **路由在界面线程执行**；而执行器的回收也在界面线程 ⇒ **两者同线程、天然串行**。
- 结论：现状**不并发**⇒ 不存在悬垂窗口；但「锁只护表不护用」这一结构性隐患仍在（路由一旦挪到别的线程即成活面）。

### 1.3 子流程残余面（P2c 登记的残余）

- 子流程节点的执行调用仍需执行器本体（那是**方法调用**，不是读面）⇒ 节点槽里除块外还留了一个执行器裸指针。
- 现状安全面：调用发生在执行线程内，而执行器的回收要**先等线程退出**⇒ 调用期间执行器不会死。

### 1.4 终局中止为何存在

- 执行线程仍会读执行器本体（工作线程的栈帧在执行器里）⇒ 若执行器在 worker 尚未退出时被析构，worker 继续访问就是野指针。
- 今日的护栏是「析构时等两段，等不到就中止进程」——**用中止换确定性**。
- 撤除它需要的是**保证**：析构发生时线程一定已经退出（不是「等二十秒大概能退」）。

## 2. 生命周期令牌（设计）

### 2.1 形状

- **对象**：一个独立的共享对象（「令牌」），持有：执行器本体（唯一拥有者）与一段「释放即收尾」的逻辑（停止 ＋ 有界等待 ＋ 回收）。
- **持有面**：界面侧（当前执行器位与流程表）、触发管理器的流程绑定、节点的残余面（子流程那一处调用）、以及执行器自身（块与令牌同生共死）。
- **不变量**：
  1. 执行器本体**只由令牌拥有**（其余持有面只持令牌）⇒ 「谁在用」与「谁负责收尾」合一。
  2. 令牌释放最后一个引用时执行收尾（停止 ＋ 有界等待 ＋ 回收执行器）⇒ **调用方不需要记得先 join**（今天需要）。
  3. 收尾**不在持有者的析构里做重活**（令牌的最后一次释放可能发生在任意线程 ⇒ 收尾须回界面线程，或令牌自带「最后一次释放必在界面线程」的约定并由座钉住）——**这一条是本期的最大风险点**，处置见 §5。
  4. 令牌不持裸指针以外的东西；执行器的场景指针、缓存三族、图索引两族、块一概不动（那些是 P2d 与图侧的事）。

### 2.2 与既有机制的关系

- 现有的回收件（停止 ＋ 有界等待 ＋ 安全回收）**逻辑不变**，只是搬进令牌（成为令牌的最后释放动作）⇒ 行为零变更。
- 令牌不替代回收件的**超时口径**（两段有界等待与「超时绝不 terminate」）——那些是现场安全口径，不动。
- 触发面与节点残余面从「裸指针」改为「持令牌」⇒ 即便将来路由挪到别的线程，执行器也不会在调用期间死 ⇒ 结构性保证。

## 3. 三步期次与判据

### P3a 令牌与持有面（结构就位，行为零变更）

- 产出：令牌件（实现与头件）；触发管理器的流程绑定改持令牌（路由的调用形不变：取出令牌 → 取执行器 → 调方法）；节点的残余面改持令牌（子流程那一处调用改为「经令牌取执行器」）。
- 判据：行为零变更（触发路由的时序与判定原样、子流程的执行语义原样）；红绿臂（红＝断开令牌在触发面上的持有 ⇒ 路由路径变脆或触发面腿红）；座（令牌面：释放一次即收尾 ＋ 多次持有只收尾一次 ＋ 收尾后执行器不可再被调用）。
- 回退：改回裸指针（三处持有面，改动面小）✓。

### P3b 销毁权归一（所有销毁路径经令牌释放）

- 产出：界面侧两处新建改为「建令牌」；回收件改为「释放令牌」；主窗析构的批量回收同样走令牌。
- 判据：行为零变更（停止时序、等待窗口、状态提示原样）；红绿臂（红＝某条销毁路径绕过令牌 ⇒ 座上「令牌释放即收尾」腿红）；既有座续绿（主窗与执行器族座）；宿主整轮。
- 回退：逐条销毁路径改回（两条新建 ＋ 两处回收）✓。

### P3c 终局中止撤除（**明示的行为变更轮**）

- 产出：执行器析构里的「两段皆尽则中止进程」换成「进入可观测终态 ＋ 现场可见的失败提示」（按已拍语义）；硬中止只留作不可达兜底（触发条件为「令牌保证下不该发生」）。
- 判据：行为变更明示（在册声明变更前后语义差：此前「进程中止」，此后「执行器进入终态并提示」）＋ 红绿臂（红＝把终态路径破坏成仍走中止或误报成功）＋ 座（终态可观测：状态与提示在场）＋ 宿主整轮。
- 前置：P3a 与 P3b 已落（否则终局撤除无依据 ⇒ **不得提前**）。

## 4. 不可动不变量（承前六条 ＋ 本期两条）

1. 锁序只许图锁 → 块锁方向（叶子无后沿）。
2. 快照与墓碑语义不变（本期不碰图侧）。
3. 停稳判定不变（停稳信号仍是唯一可改图依据）。
4. 终局中止形态不早于 P3c 撤除。
5. 账簿「键用即止」纪律不放宽。
6. 所有权化不得改变可见图结构来源。
7. **新增**：回收件的**超时口径**（两段有界等待与「超时绝不 terminate」）不动——那是现场安全口径，不因令牌化而放宽。
8. **新增**：令牌的**收尾必须发生一次且只一次**（多持有者只收尾一次；收尾后执行器不可再被调用）——由座钉住。

## 5. 风险与未决

| 项 | 内容 | 处置 |
|---|---|---|
| R-1 | **最后释放者的线程**：令牌的最后一次释放可能发生在工作线程或析构线程 ⇒ 收尾（等待与回收）若在那里执行，可能阻塞非界面线程 | 令牌设计为「收尾动作回界面线程执行」（如经信号投递）或「只允许界面线程释放」并由座钉住；本期先量清释放点的线程面再定形 |
| R-2 | 触发面与节点残余面改持令牌后，**令牌环**风险（执行器持令牌、令牌持执行器） | 令牌**不持执行器的所有权之外的任何东西**、执行器不持令牌（块与令牌分开）⇒ 无环；座上以「持面集合」断言钉住 |
| R-3 | 「最后一次释放」与「界面侧想立刻回收」两种期望的差异（现回收件是**同步**回收：调用方等它停干净） | P3b 保留同步语义（界面侧显式释放并等收尾完成），令牌的最后释放只作为兜底 ⇒ 行为零变更 |
| N-1 | 令牌是否需要与「块」合并 | **不合并**（块的语义是运行态与取消信号，令牌的语义是生命周期与收尾；合并会让「读面」与「收尾」耦合）——分开，各司其职 |
| N-2 | 终局撤除后的「执行器终态」如何对界面可见 | 沿用既有信号面（停止与错误信号）＋ 状态栏提示；具体形态在 P3c 期定 |

## 6. 与 P2d 的关系

- P2d（快照与墓碑共享所有权化）牵涉**场景成员集与节点销毁时机**，风险高于本期；本期**不依赖**它，也不阻塞它（两条线互不前置）。
- 若 P2d 先落，令牌持有面里可能要多持一份「场景侧快照」——届时按 P2d 的形调整，不在本期预留。

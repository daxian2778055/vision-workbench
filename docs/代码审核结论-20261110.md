## 二、本轮修掉的 4 项（确定性、改动可控，均带腿）

### 1. gtd 导入半残文件会静默清空全部现场通信配置（最严重）

`CommunicationManagerDialog.cpp:227-247` 旧版只校验 `format`。
`{"format":"visionflow-communication"}` 这种半残文件会通过校验，
随后 `CommunicationManager::fromJson({})` **无条件清空**设备/接收事件/发送事件/响应配置，
`GlobalTriggerManager` / `HeartbeatManager` 同样被清空 —— 用户点一次「导入」就丢光配置。

修法：
- 校验 `version == 1`；
- 三个顶层块必须存在且各自的数组键是 array（`devices` / `receiveEvents` / `sendEvents` /
  `triggers` / `heartbeats`），**在动任何配置之前**拒收；
- 按钮入口 `onImportGtd` 加整包覆盖确认（`QMessageBox::question`，默认 No）；
- 导出改 `QSaveFile` 原子写并检查实际写入字节数，防止半截文件反过来毒害导入。

腿：`tests/comm_writeback_test.cpp` 在既有 gtd 腿里补 4 种半残载荷，
断言全部拒收且 `GTD_DEV` 仍在。

### 2. FINS/TCP 正常分片被当成脏帧清空（真机会永久失步）

`FinsFrame.cpp:64-73` 旧版 `parseTcpHeader` 要求缓冲 ≥20 字节、
且 `len <= buf.size()-4`。这把**长度合法但数据未收齐的正常半包**判成解析失败；
`FinsCommNode.cpp:251-258` 随即清空整段接收缓冲。真机 TCP 分片下链路反复超时重连。

修法：帧头 16 字节即可解析；只校验长度上界（1 MB），
「是否收齐」完全交给调用方用 `headerBytes > m_rxBuffer.size()` 判断；
调用方脏帧判定阈值同步改为 16 字节。

腿：`tests/fins_test.cpp` 更新旧语义断言（长度仅比缓冲大不再算非法），
新增「只收到 16 字节帧头」与「短 1 字节」都能解析且 `headerBytes` 正确的断言。

### 3. 子界面圆角保存后丢失

`RuntimeInterface.cpp:331-339 / 515-525` 的 `cornerRadius` 只在 `RunStatus` 分支读写，
而 `RuntimeInterfaceDesigner.cpp:2386` 允许给 `SubInterface` 设圆角、
`RuntimeInterfaceView.cpp:1350` 会用它 ⇒ 保存后变回 0。

修法：toJson/fromJson 改成 `RunStatus || SubInterface` 共用，保留 0..40 钳制。

腿：`UiGuardsTest::subInterfaceCornerRadiusRoundTrips`（含 RunStatus 钳制回归）。

### 4. 撤销快照漏了第三层隐式共享 + 定时器收口

`pushUndo()`（B1f）只 detach `pages` 和 `pages[].controls`，
但 `RuntimeInterface::subPages` 也是隐式共享容器，`effectivePage()` 返回其中元素的裸指针 ——
子界面编辑态下同样会污染快照。

修法：抽出 `detachLayoutSnapshot()` 统一做三层 detach（含 `subPages` 及其 `controls`）；
`undo()/redo()` 停止挂起的 600ms 属性合并定时器。

**一次自我纠错**：我最初在 `undo()/redo()` 里也调了 `detachLayoutSnapshot`，
结果 `UiGuardsTest` 在 `-j 4` 下稳定访问违规（`0xC0000005`，崩在 `invokeMethod("undo")`）。
对照实验关掉该句后单腿连跑 **5/5 通过**，恢复用户原逻辑后两次全量并行 80/80。
原因想清楚了：**快照在 `pushUndo()` 入栈时已彻底自持，取出时无需再 detach**，
那两处是我过度修复。代码里留了注释记录这次实验，避免以后又加回去。

## 三、审核发现但本轮未修（需要真机报文或产品决策，不擅自改）

### A. FINS 协议（无真机，不能凭代码定案）

- **`readMemoryParams/writeMemoryParams` 的字节布局疑似不符 W342**
  （`FinsFrame.cpp:128-139`）：组出「区码(1) + 固定 `0x00`(1) + 地址U16 + 字数U16」，
  但规范通常是「区码(1) + 起始地址(2) + 位号(1) + 项数(2)」，位区码/位偏移完全未实现。
  代码、文档、测试三者自证同一口径，**必须用真机报文或 W342 原文确认后修**。这是最该优先的一项。
- **FINS 测试自证闭环**：`fins_test.cpp:395-398` 的写帧期望由被测函数 `Fins::command()` 自己生成；
  回环 mock 服务端也用被测函数造帧/拆帧且不解析请求参数。组包口径错了测试仍绿。
  建议改独立硬编码 + mock 独立解析。
- FINS 写寄存器 `writeRegister` 在产品中**无调用点**（只有测试能触发）；
  `noteSendWriteFailure` 未接（写失败不会让本轮判 NG）；
  FINS/UDP 默认节点号 0/0 静默发无效帧、响应不校验来源；
  读轮询遇配置错误静默 `continue`；`encodeValue` 的 `qint64(double)` 越界 UB；
  JSON 直载路径节点号无钳位（`& 0xFF` 静默回绕）。
- 实测 `fins_test` **9 passed**，审核报告里的「7 个槽 / 文档写 8 条」口径过时，以实测为准。

### B. 通信管理 UI

- **删除/重命名设备的悬空引用**：心跳仍按旧名监控、响应配置 device 不跟随、
  事件 `deviceName` 悬空（`CommunicationManager.cpp:122-195`、`HeartbeatManager.cpp:118-142`）。
- **「完全一致的参数」未全协议生效**：数据上传显示面无门禁、
  接收结束符对 Modbus/PLC/FINS 绕过组帧、自定义结束符留空静默退化、UDP 数据报被拼接。
- `executionStopped`（手动停止/错误/空场景终态）不发 IDLE 响应；
  `responseSent` 信号全仓只 emit 无 connect，发送失败只有 `VFP_DEBUG`，UI 不可见。
- `RegisterSpaceBar`：地址溢出、清空不可撤销、`m_blankHidden` 只写不读、Esc 后按钮状态不复位。
- gtd 格式是**本仓自有 JSON**，与 VM 私有 `.gtd` **不互通**（文档已声明）；
  是否要求与真机互通属产品决策。

### C. 运行界面

- 撤销栈仍有漏网路径：B3 新增属性 lambda、对齐/分布、子界面属性编辑、`loadLayout()` 未清栈。
  本轮只补了「快照自持」，没把这些路径统一收口到 `pushUndo()`。
- 子界面密码**明文存储 + 非常量时间比较**；`fromJson()` 不拒绝环/超深，
  BFS 只防死循环不拒绝环。改密码格式会影响已存布局，需产品拍板。
- 多页运行视图的几何计算与审核报告口径有出入（报告说按当前页算所有页，
  但已有 `multiPageGeometryUsesPageContainerBase` 腿），**建议现场切页实测**再定。
- 跨线程 queued lambda 持裸 `NodeBase*`；`liveViews()` 无 `QPointer`/锁；
  `UiLogBus` 无锁且直写 `QPlainTextEdit`。需确认所有 `logMessage()` 都在 GUI 线程。
- 图表未过滤 `NaN/Inf`；Qt6Charts 间接依赖在目标机是否被 `windeployqt` 完整覆盖需装机确认。
- 注释与实现不符：`RuntimeInterface.h:136-138` 仍写「旧 `bindKey` 加载时自动合成动作」，
  但项目已声明不做旧兼容、实现只读 `actions`（运行视图有 fallback，行为未丢）。

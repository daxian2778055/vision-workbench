# 代码审查流程指南

## 概述

本指南为 VisionFlowPlatform 项目建立标准化的代码审查流程，确保代码质量、安全性和可维护性。

## 代码审查目标

1. **质量保证**：确保代码符合项目标准和最佳实践
2. **知识共享**：促进团队成员之间的知识传递
3. **风险控制**：识别和修复潜在的安全和性能问题
4. **持续改进**：通过反馈循环不断改进开发流程

## 审查流程

### 1. 提交前准备

#### 开发者自检清单
- [ ] 代码编译通过，无警告
- [ ] 单元测试通过
- [ ] 静态分析工具检查通过
- [ ] 代码符合项目编码规范
- [ ] 添加必要的注释和文档
- [ ] 更新相关文档

#### 提交信息规范
```
<类型>(<范围>): <简短描述>

<详细描述>

<相关Issue>
```

**类型**：
- `feat`: 新功能
- `fix`: 修复bug
- `docs`: 文档更新
- `style`: 代码格式调整
- `refactor`: 代码重构
- `test`: 测试相关
- `chore`: 构建/工具相关

### 3. 审查过程

#### 审查者检查清单

##### 代码质量
- [ ] 命名规范是否符合项目标准
- [ ] 代码是否清晰易懂
- [ ] 函数长度是否合理（<50行）
- [ ] 是否有重复代码
- [ ] 注释是否充分且有用

##### 内存管理
- [ ] 是否正确使用智能指针
- [ ] 是否有内存泄漏风险
- [ ] Qt对象父子关系是否正确
- [ ] HALCON对象是否正确管理

##### 线程安全
- [ ] 跨线程信号槽是否使用正确连接类型
- [ ] UI操作是否在主线程
- [ ] 共享数据是否有适当保护
- [ ] 是否有死锁风险

##### 性能
- [ ] 是否有不必要的拷贝
- [ ] 容器选择是否合适
- [ ] 算法复杂度是否合理
- [ ] 是否有性能瓶颈

##### 错误处理
- [ ] HALCON调用是否有异常处理
- [ ] 文件操作是否有错误检查
- [ ] 错误信息是否有用
- [ ] 错误是否正确传播

##### 安全性
- [ ] 是否有SQL注入风险
- [ ] 是否有缓冲区溢出风险
- [ ] 是否有敏感信息泄露
- [ ] 是否有权限控制问题

##### Qt特定
- [ ] 信号槽参数类型是否注册
- [ ] 是否有内存泄漏
- [ ] 是否阻塞事件循环
- [ ] UI更新是否在主线程

##### HALCON特定
- [ ] 算子选择是否合适
- [ ] 参数是否有效
- [ ] 资源是否正确释放
- [ ] 是否有性能优化空间

#### 审查评论规范

##### 评论类型
- **严重问题**：必须修复，阻塞合并
- **警告**：建议修复，不阻塞合并
- **建议**：可选优化，供参考
- **问题**：需要澄清的疑问
- **肯定**：好的实践，值得学习

##### 评论格式
```markdown
**[类型]** 位置：文件:行号

**问题描述**：
[清晰描述问题]

**建议修复**：
```cpp
// 修复代码示例
```

**原因**：
[解释为什么需要修复]
```

### 5. 审查完成

#### 合并条件
- [ ] 所有严重问题已修复
- [ ] 审查者已批准
- [ ] CI/CD 流水线通过
- [ ] 文档已更新
- [ ] 测试覆盖率达到要求

## 审查工具

### 1. 静态分析工具集成

#### cppcheck 集成
```bash
# 在审查前运行
cppcheck --enable=all --suppress=missingInclude src/ include/

# 生成报告
cppcheck --enable=all --xml --xml-version=2 src/ include/ 2> cppcheck-results.xml
```

#### clang-tidy 集成
```bash
# 在审查前运行
clang-tidy -p build src/*.cpp

# 自动修复
clang-tidy -p build --fix src/*.cpp
```

### 2. 代码质量工具

#### 代码行数统计
```bash
# 统计代码行数
find src include -name "*.cpp" -o -name "*.h" | xargs wc -l
```

#### 复杂度分析
```bash
# 使用 lizard 分析复杂度
pip install lizard
lizard src/*.cpp
```

### 3. 测试覆盖工具

#### gcov 集成
```bash
# 编译时启用覆盖率
cmake -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS="--coverage"
cmake --build build

# 运行测试
ctest

# 生成覆盖率报告
gcov src/*.cpp
lcov --capture --directory . --output-file coverage.info
genhtml coverage.info --output-directory coverage_report
```

## 审查角色

### 1. 开发者职责
- 编写高质量代码
- 进行自检
- 准备审查请求
- 响应审查反馈
- 修复问题

### 2. 审查者职责
- 及时响应审查请求
- 提供建设性反馈
- 指导最佳实践
- 知识分享
- 质量把关

### 3. 维护者职责
- 维护审查流程
- 更新审查标准
- 培训新成员
- 工具配置
- 流程改进

## 审查频率

### 1. 常规审查
- **频率**：每次提交
- **范围**：所有代码变更
- **时间**：24小时内完成

### 2. 架构审查
- **频率**：重大变更时
- **范围**：架构设计、接口变更
- **时间**：48小时内完成

### 3. 安全审查
- **频率**：安全相关变更
- **范围**：安全敏感代码
- **时间**：72小时内完成

## 审查指标

### 1. 质量指标
- **缺陷密度**：每千行代码缺陷数
- **审查覆盖率**：审查的代码比例
- **问题修复率**：发现问题的修复比例
- **审查时间**：平均审查时间

### 2. 效率指标
- **审查周转时间**：从请求到完成的时间
- **问题发现率**：每次审查发现的问题数
- **返工率**：需要重新审查的比例
- **自动化率**：自动检查的比例

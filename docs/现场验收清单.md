# 现场验收清单

**用途**：装机后照此表逐项打勾，作为交付验收记录。全部「预期」成立即通过；任一项不符，按最后一节的**分诊表**先自查，再联系开发。

**谁做 / 用时**：实施人员，约 **25–40 分钟**（不含训练实际耗时）。
**需准备**：`rc-` 装机包（含 `train-env/`）、一台可用相机或一个图片目录、一台训练机（如需演示训练）。

> 打勾方式：每行「✓ / ✗」，✗ 行在备注写现象与时间。整表签字后随交付单归档。

---

## 1. 包完整性（不启动程序，先核文件）

| # | 步骤 | 预期 | 失败先查 |
|---|---|---|---|
| 1.1 | 打开包内 `版本说明.txt`，找到「VisionFlowPlatform.exe md5」 | 有一行 32 位 md5 | 包是否是完整拷贝（对比传输后的 md5） |
| 1.2 | 对 `VisionFlowPlatform.exe` 计算 md5（`certutil -hashfile VisionFlowPlatform.exe MD5`） | **与 1.1 完全一致** | 拷贝过程损坏；或包与说明不是同一次打包 |
| 1.3 | 看 `版本说明.txt` 的「exe 内嵌 HEAD 版本哈希」 | 必须是 **yes** | 打包前未重新构建——该包不可交付 |
| 1.4 | 确认包内存在 `train-env/` 目录与其中 `wheels/` | 目录存在，`wheels` 内有若干 `.whl` | 该包未带离线环境；产线机可不需要，训练机需要 |
| 1.5 | 确认包内存在 `docs/现场验收清单.md`（本文件） | 存在 | 旧包；以最新 `rc-` 为准 |

## 2. 首次启动与账号

| # | 步骤 | 预期 | 失败先查 |
|---|---|---|---|
| 2.1 | 双击 `VisionFlowPlatform.exe` | 主窗口正常出现，无缺 DLL 报错 | 包不完整；VC 运行库；杀软拦截 |
| 2.2 | 菜单「帮助 → 关于」 | 显示 `(提交号 / 日期)`，与 `版本说明.txt` 的提交一致 | 装错包（用了别的构建） |
| 2.3 | 用 `admin / admin` 登录 | 登录成功 | 数据库未首次初始化的表现是「账号不存在」；确认 exe 目录可写 |
| 2.4 | 在未改密状态下试着新建节点 / 保存方案 | **被拦**，提示指向「系统 → 修改管理员口令」 | 若**没被拦**，说明写闸失效——记缺陷，不要继续 |
| 2.5 | 「系统 → 修改管理员口令」改成新口令 | 改密成功 | 口令长度限制（≥6 位） |
| 2.6 | 重新登录新口令，再新建节点并保存 | 正常保存 | 写闸未解除 → 记缺陷 |

> **2.4 是必测项**：它验证「默认口令未改时不允许写入」这条保护是否生效。

## 3. 流程搭建与运行

| # | 步骤 | 预期 | 失败先查 |
|---|---|---|---|
| 3.1 | 工具箱拖入一个图像源（相机或图片目录）+ 一个算子，连线 | 连线成功；端口类型不匹配时拒绝并提示 | 端口类型；输入端口已占用需先断开 |
| 3.2 | 保存方案 | 成功，无「保存失败」提示 | 写闸（见 2.4）；目录权限 |
| 3.3 | 点「开始」，连续模式跑 10 秒 | 画面持续刷新，状态栏显示轮次与耗时 | 相机索引/曝光；算子报错看日志区 |
| 3.4 | 点「停止」 | 立即停在空闲态；**画布解锁** | 未解锁 → 记缺陷 |
| 3.5 | 再点「开始」，跑完一轮后让流程自行结束（单次/触发） | 结束后 **画布解锁、菜单可用** | 菜单仍灰 → 记缺陷（历史缺陷点，已修） |
| 3.6 | 运行中点「暂停」 | 停稳后**允许改画布**；「继续」后恢复运行并**重新上锁** | 锁状态与菜单不一致 → 记缺陷 |

## 4. 标注（检测框）

| # | 步骤 | 预期 | 失败先查 |
|---|---|---|---|
| 4.1 | 「系统 → 检测框标注…」，选一个含 `.png` 的目录 | 图片列表出现；首图显示在画布 | 目录内无图片；目录不可读 |
| 4.2 | 在图上拖拽画一个框 | 框出现，右侧列表多一行 | 拖得太小会被忽略（有提示） |
| 4.3 | 切换图片再切回 | 框**仍在**（切换即保存，且存到**原来的那张**） | 回来框没了 → 记缺陷 |
| 4.4 | 在图上点选一个框 → 删除 | 框消失，提示「已删除，剩 N 个框」 | 保存失败会**撤回**并提示原因 |
| 4.5 | 清空本图 | 框全清，提示写出空 txt（= 该图无目标） | 同上 |
| 4.6 | 直接点右上角 × 关窗 | 当前图的框**已保存**（再打开仍在） | 关窗丢框 → 记缺陷 |
| 4.7 | 打开该图同名 `.txt` | 每行 `类别 cx cy w h`，归一化（0–1） | 格式错 → 记缺陷 |

## 5. 训练（仅在训练机上做；产线机可跳过整节）

| # | 步骤 | 预期 | 失败先查 |
|---|---|---|---|
| 5.1 | 「系统 → 训练…」，确认「Python 路径」指向训练环境 | 标签变绿「环境就绪」 | 见仓库 `deploy-extras/train-env/README.md`（装机包里是 train-env 目录下的同名说明）；未装 torch 会显示 import 失败 |
| 5.2 | 点「检测环境」后立刻拖动窗口 | **界面不冻结**（后台探测） | 冻结 → 记缺陷（历史缺陷点，已修） |
| 5.3 | 选数据集目录、训练器，点「开始训练」 | 日志逐行滚动，有进度信息 | 数据集路径/类别文件缺失；命令预览可复制去命令行复现 |
| 5.4 | 训练中点「取消训练」 | **不卡界面**；约 5 秒后未退出会强制结束 | 卡住数秒 → 记缺陷 |
| 5.5 | 训练中点窗右上角 × | **拒绝关闭**并请求取消；进程收尾后**自动关闭** | 直接关掉、进程被杀 → 记缺陷 |
| 5.6 | 训练完成 | 日志给出产出（`best.onnx` 等），可复制路径 | 判别是训练失败还是导出失败（看最后 20 行） |

## 6. 计数闭环

| # | 步骤 | 预期 | 失败先查 |
|---|---|---|---|
| 6.1 | 新建「目标计数」类节点，选 `best.onnx` + `classes.txt` | 新图能解出框（右侧计数上升） | **输出布局**选错（v8/v11 与 v5/YOLOX 不同）；`缩放系数` 必须 >0 |
| 6.2 | 同一模型接到「检测」节点 | 框与类别都正确 | 类别全错 = 布局选反 |
| 6.3 | 设过线线（两个点），让目标穿过 | 计数 +1；反向穿越按方向设置计或不计 | 方向模式；线是否跨在目标路径上 |
| 6.4 | 让目标**先反向再正向**穿过 | 只计 **1** 次 | 计 2 次或 0 次 → 记缺陷 |
| 6.5 | 按批清零（触发一次清零） | 累计归零，跟踪状态清空 | 清零参数是否启用 |
| 6.6 | 「文件 → 打包模型与依赖…」选输出目录 | 生成方案 + `assets/`，模型被复制进去 | 写闸/运行中会被禁用（设计如此） |
| 6.7 | 把打好的目录拷到另一台机器打开 | 流程可开、模型路径指向包内、能直接跑 | 模型仍指向原机器路径 → 记缺陷 |

| 结论 | 条件 |
|---|---|
| **通过** | 1.x、2.x、3.x、4.x、6.x 全 ✓（5.x 若演示训练则同样要求全 ✓） |

## 8. 失败分诊表（先自查，再找开发）

| 现象 | 第一步查什么 | 常见原因 |
|---|---|---|
| 启动即退出/缺 DLL | 包是否完整（1.2）；杀软日志 | 拷贝不全；VC 运行库未装 |
| 登录提示账号不存在 | exe 目录是否可写；数据库文件是否生成 | 目录只读导致首次播种失败 |
| 能进但**改不动**画布 | 是否已改默认口令（2.4） | 写闸生效（这是设计） |
| 方案保存失败 | 目标目录权限；盘是否满 | 只读目录 / 磁盘满 |
| 运行时画面不刷新 | 相机索引、曝光；日志区首条错误 | 设备被占用 |
| 点停止后仍不能编辑 | 状态栏是否显示 Idle | 锁未释放 → 缺陷 |
| 标注关窗后框丢了 | 该图同名 `.txt` 是否生成 | 目录只读 / 写失败未提示 → 缺陷 |
| 框解不出来 / 计数恒 0 | 布局参数、`缩放系数`、`confThresh` | 布局选反；缩放系数为 0（历史缺陷，已修） |
| 类别全错 | 输出布局 | v5/YOLOX 与 v8/v11 混用 |
| 训练环境一直「不可用」 | 该 Python 能否 `import torch` | 环境未装 / 版本不匹配 |
| 训练日志中文乱码 | 控制台编码 | Python 输出编码，非功能缺陷 |
| 打包后换机打不开模型 | `assets/` 内是否有该模型 | 打包时目录不可写 |

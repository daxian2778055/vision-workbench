# FlowExecutor 共享化 —— P2 期设计面

> 性质：**设计面**——零代码零行为；P2 期（快照与墓碑共享所有权化 ＋ 执行器存活控制块）的编码前设计，先量后定。
> 触发：客户复核与切片 C 拍板回执（附表第二百零七条）拍定「接受节点壳与非对象状态体分离，并据此启 P2 期，走分层共享路线」。
> 依据：HEAD 态读侧逐点实测（算子侧到底从执行器身上取什么），非估计；面索引见 §7。
> 关系：本件只设计 **P2 期**；P3（销毁权收口 ＋ 触发面使用期）与 P4（撤终局中止）不在本件范围内，只在 §5 标出边界。

## 0. 结论先行

| 项 | 结论 |
|---|---|
| P2 的核心 | 把**算子需要的东西从执行器主体上摘下来**，搬进一个可共享的「运行上下文块」；算子此后只持块、不持执行器 ⇒ **工作线程不再读执行器主体**（终局三条件之 T1 在节点侧达成） |
| 块里放什么 | 只放四项（实测收敛）：**运行态**、**运行模式**、**上下文存在性**、**取消信号**（可取消等待：停则醒、暂停不扣预算） |
| 块不放什么 | 场景指针、缓存三族、图索引两族、执行队列、触发路由——那些属图侧与 P3，不进本块 |
| 期次 | 三步：**P2a** 块与承载（纯新增）→ **P2b** 执行器侧写入（状态与取消信号改写进块）→ **P2c** 算子侧改持（节点归属指针与单例兜底改持块，算子不再调执行器） |
| 判据 | 每步独立轮、行为零变更、红绿臂（红恰破坏腿 ＋ 还原终绿两枚面）、新座双注册、宿主整轮、附表落笔照用 |
| 锁序 | 块锁是**叶子**（与账叶锁同级），**两者不得嵌套持有**；图锁 → 块锁的既有单向序保持 |

## 1. 读侧需要什么（实测）

算子侧从执行器身上取的东西只有四类，全部与「执行器主体的其余部分」无关：

| 读侧 | 位置形态 | 要的东西 |
|---|---|---|
| 延时节点 | 归属执行器存在时走「可取消等待」，否则退化为普通睡眠 | **取消信号**（停则醒且返回未完成；暂停期间不扣延时预算） |
| 脚本节点（三处） | 读归属执行器的状态，判是否已停止（是则杀进程并回收作业） | **运行态**（只读） |
| 子流程节点 | 判有没有执行器上下文（无则按设计期空转成功并清输出） | **上下文存在性** |
| 图像源节点（三处） | 归属执行器优先、否则回落全局单例；读运行模式与运行态 | **运行模式** ＋ **运行态** ＋ **上下文存在性（带单例兜底）** |

**读侧的共同形状**：读的都是**数据**（状态、模式、存在性），加上**一个可取消等待的动作**；**没有一处需要执行器主体的方法**（除了「可取消等待」这一个动作，而它本质是「状态 ＋ 取消信号」的组合）。⇒ 把这四类搬进一个共享块后，算子侧对执行器主体的依赖归零 ✓。

## 2. 共享块的形状

### 2.1 名字与形态

- 面名候选：**运行上下文块**（`FlowRunContext`）——一个纯值型共享对象（非 QObject、不进任何父子树、可被多线程引用）。
- 持有方式：执行器持一份强引用；节点的「归属槽」持一份强引用（块小、生命周期与节点同长即可）；全局单例位持「最近一份」的强引用（替代今天的裸指针单例位）。
- 块内字段（就四项，全部是读多写少）：
  - 运行态（原子量，取值域与今天的执行状态枚举同序——**值域与序不变**，避免下游判读漂移）；
  - 运行模式（原子量，取值域与今天的运行模式枚举同序）；
  - 取消信号（互斥量 ＋ 等待条件，与今天的执行器内那对同形）；
  - 上下文存在性（块的「已建立」标志；节点判「有没有执行器上下文」用它，不判指针非空）。

### 2.2 不变式（钉死，P2 三步都必须守住）

1. 块内**不持有任何裸指针**（不放场景、不放节点、不放执行器）⇒ 块的生命周期与执行器主体解耦 ⇒ 执行器可以先死，块仍可被读 ✓。
2. 块的互斥量是**叶子**：持块锁期间不得再取任何别的锁（含图锁与账锁）——与账叶锁同级，**两者不得同时持有**。
3. 块的写入只有执行器侧一处（状态迁移、模式变更、取消信号）；算子侧只读状态与模式，写入仅「请求取消」这一个动作 ✓（写面收敛，便于推演）。
4. 状态迁移的**值与时机**与今天逐点同形（起跑、暂停、停、结束、错误各在哪一步改状态）——行为零变更的基准就在这四条上。
5. 「可取消等待」的**唤醒时机与预算语义**与今天同形（停止即醒并返回未完成；暂停期间不扣预算；恢复后继续扣）。

### 2.3 锁序落位

- 今天的既有单向序：**图锁 → 执行器状态锁**（执行器内那对状态锁与等待条件即本块要搬走的那对）。
- 搬进块之后：**图锁 → 块锁**（单向不变）✓；块锁是叶子 ✓；账叶锁是另一叶子 ✓；**块锁与账锁不得嵌套**（本期内两者的持有点不重叠 ✓——记账在界面侧、块锁在执行线程侧与算子侧 ✓）。
- 取锁点盘点（设计期先量）：状态写入点（执行器线程）、状态读取点（算子线程与界面线程）、取消等待点（算子线程）、记账点（界面线程）——四类之间无同点嵌套 ✓。

## 3. 三步期次与判据

### P2a 块与承载（纯新增，零行为变更）

- 产出：块的实现与头件；块自身的行为座（状态迁移与取消信号的语义断言：停则醒、暂停不扣预算、恢复续扣、模式与状态的读写可见性）。
- 判据：行为零变更（今天没有块 ⇒ 座是纯新增件的语义钉）；红绿臂自证（红＝破坏取消信号或暂停预算语义）；座双注册；宿主整轮。
- 回退：删掉该件即可（无调用方）✓。

### P2b 执行器侧写入（状态与取消信号改写进块）

- 产出：执行器持有块；状态迁移点与模式变更点与取消信号改写到块；执行器自身的状态读取改从块读（内部一致性）。
- 判据：行为零变更（状态值与时机与唤醒语义逐点同形）；红绿臂（红＝破坏一处状态迁移的时机或唤醒语义）；既有座续绿（执行器族座与集成座）；宿主整轮。
- 回退：切回执行器内那对状态锁与等待条件（改动集中在状态读写点，可逐点回）✓。

### P2c 算子侧改持（节点归属槽与单例兜底改持块）

- 产出：节点的「归属槽」从裸执行器指针改为块引用；全局单例位从裸指针改为块引用；四类读侧改读块（延时节点走块的可取消等待；脚本与子流程与图像源节点读块的状态与模式与存在性）。
- 判据：行为零变更（同一状态值、同一存在性判定、同一唤醒时机）；红绿臂（红＝破坏存在性判定或状态读取）；新座（算子侧读面：设计期无上下文时按空转成功处理、暂停与停止下的三种读面）；宿主整轮。
- 回退：节点的归属槽改回裸指针（读侧只有四类，改动面小）✓。

## 4. 不可动不变量（承词条六条 ＋ 本期新增一条）

1. 锁序只许图锁 → 块锁方向（叶子无后沿）。
2. 快照与墓碑语义不变（持有期不因本块延长；墓碑 flush 仍在场景线程——本块不碰图侧 ✓）。
3. 停稳判定不变（停稳信号仍是唯一可改图依据）。
4. 终局中止形态不早于 P4 撤除（本期不动它）。
5. 账簿「键用即止」纪律不放宽（本期不碰账簿）。
6. 所有权化不得改变可见图结构来源（快照仍来自场景成员集拷贝）。
7. **新增**：**块不得成为算子回调执行器主体的通道**——算子只读块的数据、只写「请求取消」这一个动作；任何「经块拿执行器指针再调其方法」的形状都判违例（这是 P2 的意义所在，也是 P3 的前提）。

## 5. 边界：本期不碰的与留给 P3 的

- **触发面**（触发管理器按流程名绑定执行器并在路由里调「请求外部触发」）：那是一条**方法调用**，共享块解决不了 ⇒ 属 P3（销毁权收口：绑定侧持一份「保证执行器活着」的持有物，析构前先join）✓。
- **全局单例的调用面**：单例今天被算子用作「归属执行器缺失时的兜底」；本块把兜底改成「最近一份块」✓（只读状态与模式 ✓ 不调方法 ✓）——但若将来有代码经单例调执行器方法，仍须走 P3 ✓。
- **图侧**（场景指针、缓存三族、图索引两族、快照与墓碑）：本期不动；快照与墓碑的共享所有权化是 P2 的另一半，须在 P2a/P2b 之后单独一步（P2d）设计（它牵涉场景成员集与节点销毁时机，风险高于前三步）✓。
- **相机与通信面**：不动。

## 6. 未决与风险

| 项 | 内容 | 处置 |
|---|---|---|
| N-1 | 「上下文存在性」的精确口径：今天子流程节点判的是「归属执行器指针非空」；换成块后判「归属槽非空」——两者在**同一节点被两个执行器先后接管**时可能不等价 | P2c 期实测该形状（先量：节点接管是否换槽），必要时把块内加一位「上下文代数」并在接管时递增 |
| N-2 | 块被多线程读写的可见性：状态用原子量、取消信号用互斥量；两者的**组合读**（读状态后立刻等取消）是否需要同一把锁 | P2a 的座里以「读-等」竞态臂实测，不足则把状态纳入块锁（代价：算子读状态要多一次加锁） |
| N-3 | 延时预算的「暂停不扣」语义在块锁下是否与今天逐点一致（今天那段循环的加锁与扣减次序） | P2a 座逐点钉（暂停、恢复、停止三种次序各一臂） |
| R-1 | 块引入新的共享面 ⇒ 出错面从「指针悬垂」变成「块的状态与主体不同步」 | 每期以「块状态 ＝ 主体状态」的对照断言钉住（P2b 期） |
| R-2 | 节点持有块的强引用 ⇒ 块比节点活得久（无害，块小且不含图侧） | 登记为已知取舍 |

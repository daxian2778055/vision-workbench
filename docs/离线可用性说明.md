# 离线可用性说明（无外网环境）

适用范围：现场/客户环境**不连外网**（工厂内网常见）。本文回答三件事：
① 现有功能分别依赖什么（有没有外网依赖）；② 怎么**一键校验**部署包离线可用；③ 哪些能力离线做不了（已关闭项）。

> 结论先行：**运行期零外网依赖**。全仓 `src/` 未发现 `QNetworkAccessManager` / `QNetworkReply` /
> `QDesktopServices::openUrl` / 任何 URL 访问代码；无联网激活、无遥测、无在线更新检查。
> 唯一的"网络"是 TCP / UDP / Modbus / 串口这类**站内通信节点**（走局域网/串口，不需要外网）。

## 2. 一键校验：部署包是否真的能在目标机离线跑起来

```powershell
powershell -ExecutionPolicy Bypass -File tools\deploy.ps1
```

脚本最后一步（Step 11「部署自检（离线可用性）」）做三项校验，**任一不过即以非零码退出**：

1. **关键文件就位**：`VisionFlowPlatform.exe`、`platforms\qwindows.dll`、`sqldrivers\qsqlite.dll`、
   `Qt6Core/Qt6Sql/Qt6Widgets.dll`、`opencv_world4130.dll`、`halconcpp.dll`、`MvCameraControl.dll`、
   `vcruntime140.dll`、`msvcp140.dll`、`tessdata`、**`dl`（DeepOCR 模型）**、`license`、`data`、`logs`、`schemes`；
2. **CRT 完备性**：扫描包内二进制**实际引用**的 VC 运行时 DLL，逐个确认都在包内
   （避免"看起来拷了、其实少一个"，这种问题在开发机上永远看不出来）；
3. **从部署目录本体跑节点自检**：`dist\VisionFlowPlatform\VisionFlowPlatform.exe --selftest-nodes`
   （**不设** `QT_PLUGIN_PATH`，模拟目标机双击）——要求退出码 0、报告 `0 FAIL`、stderr 无 `QSQLITE` 告警。

跳过校验用 `-SkipVerify`（只在明确知道环境情况时用）。

## 3. 目标机环境要求（无法打包进 zip 的部分）

- Windows 10 / 11 x64；
- **VC++ 2015-2022 x64 可再发行包**：脚本会尽量把 CRT 随包拷贝；若制作包的本机未装 Visual Studio
  （找不到官方 redist 目录），请确认目标机已安装该可再发行包；
- 使用 MVS 相机：目标机安装 MVS 客户端（或使用随包运行时 + 相机驱动）；
- 使用 HALCON 算子：**无需安装 HALCON**（运行库与 `dl/` 模型随包，启动时自举 `HALCONROOT`）；
  若现场另有正式 License，放进 `<包>/license/` 即可；本机实测**没有** `license*.dat` 也能跑 DeepOCR；
- 使用脚本节点：安装 Python，并在「脚本安全」中配置解释器全路径。

## 4. 离线问题排查

| 症状 | 处置 |
|---|---|
| 双击无反应 / 提示缺 DLL | 先看包内 `部署说明.txt`；多数是 CRT 或 HALCON / MVS 运行库缺失。可先跑第 2 节自检定位 |
| 提示 `QSQLITE` / 数据库不可用 | 确认 `sqldrivers\qsqlite.dll` 与 `Qt6Sql.dll` 与 exe 同目录（自检会直接报出来） |
| 脚本节点报"未找到 Python 解释器" | 目标机未装 Python 或未配置路径（安全设计为 fail-closed，不会静默跳过） |
| ONNX 节点报"模型加载失败" | 模型文件需本地存在；本平台不提供在线下载 |
| 相机枚举不到 | 与本机网络无关的常见原因：MVS 客户端能否枚举、GigE 网卡 IP 是否与相机同网段 |

## 5. 本轮修掉的一个真离线缺陷（留档）

- **现象**：部署包缺 `vcruntime140.dll` / `vcruntime140_1.dll` / `msvcp140.dll` 等 VC 运行时。
  本机（开发机）装了系统级 CRT，所以**在开发机上怎么点都正常**；到干净目标机会直接"缺少 DLL 打不开"。
- **原因**：`windeployqt` 只有设置了 `VCINSTALLDIR`（即装了 Visual Studio）时才会自动处理 CRT；
  本机未装 VS，它会跳过并以**非零码**返回——而部署脚本原先只记一条 warning 就继续了。
- **处置**：`tools/deploy.ps1` 新增 **Step 5.8「拷贝 MSVC 运行时 (CRT)」**（优先官方 redist，
  兜底本机已安装运行时），并把 **CRT 引用完备性**纳入部署自检（第 2 节第 2 项）。
  留档原因：这类"开发机永远复现不了"的缺陷，只有把校验写进脚本才不会复发。

## 6. 免安装 HALCON：DeepOCR 随包运行（2026-11-07 实测）

- **背景**：DeepOCR 靠 `CreateDeepOcr` 从 `%HALCONROOT%/dl` 加载预训练模型。早期部署只拷了
  HALCON DLL（61 个），**没拷 `dl/*.hdl`**，于是出现「开发机能用、目标机报缺模型」。
- **处置**：
  1. `tools/deploy.ps1` 新增「拷贝 DeepOCR 预训练模型」步骤（3 个 `.hdl`，约 214 MB；
     包体积因此增到约 1.5 GB）；
  2. `src/main.cpp` 启动最早期自举：`HALCONROOT` 未设置时指向 `exe` 所在目录
     （显式设置的环境变量优先、不覆盖），于是 HALCON 从 `<包>/dl/` 找模型、`<包>/license/` 找授权。
- **实测**：在完整包目录内清空 `HALCONROOT`、并把 HALCON 路径从 `PATH` 移除后运行
  `VisionFlowPlatform.exe --selftest-nodes` → `71 PASS / 0 FAIL / 4 SKIP`，含 `OK DeepOcrNode`。
- **结论**：目标机**不需要安装 HALCON、不需要单独配 license**，拷贝整个目录双击即可。

## 7. HALCON 运行库瘦身：587 MB → 157 MB（2026-11-08 实测）

- **动机**：本平台真正调用 HALCON 算法的只有 DeepOCR；早期部署把 `bin/x64-win64` 下
  **全部 61 个 DLL（587 MB）** 都拷进包，其中大部分与本平台无关。
- **实测方法**：在完整包内把下列 DLL 移出，再清空 `HALCONROOT` + 移除 PATH 跑
  `--selftest-nodes`，要求 `0 FAIL` 且 `OK DeepOcrNode`。
- **保留（8 个，约 157 MB）**：`halcon.dll`、`halconcpp.dll`、`halcondl.dll`、`halconc.dll`、
  `libiomp5md.dll`、`libcrypto-3-x64.dll`、`libssl-3-x64.dll`、`d3dcompiler_47.dll`。
- **移出（54 个，约 429 MB）** 及理由：

| 类别 | 体积 | 不用的理由 |
|---|---|---|
| `Qt5*MVTec.dll`（含 `Qt5WebEngineCoreMVTec` 96.8 MB） | ~120 MB | 本平台用 Qt6，HALCON 自带的 Qt5 只服务于它的 HDevelop/Web 组件 |
| `*xl.dll`（halconxl / halcondlxl / halconcppxl / halconcxl） | ~148 MB | 「XL」是大图/大内存变体，与常规尺寸互斥，本平台不链接 |
| `hdevenginecpp*.dll` | 54.5 MB | HDevelop 引擎（执行 .hdev 程序），本平台不执行 HDevelop 代码 |
| `hAcq*.dll`（GigE / USB3 / GenICam / RealSense / File / DirectFile / MediaFoundation） | 46.4 MB | 采集走海康 MVS，不用 HALCON 采集插件 |
| `hio*` / `uastack`（OPC UA / Hilscher Profibus） | 3.8 MB | HALCON 的工业通讯栈，本平台用自有通讯节点 |
| `opengl32sw` / `libGLESv2` / `libEGL` | 23.4 MB | 软件 OpenGL 兜底，Qt6 自带渲染路径 |
| `hAI2*`（TensorRT / OpenVINO 加载器） | 4.3 MB | DeepOCR 默认运行时不需要这些推理后端 |
| `MediaInfo` / `libwdi` / `libusb` / `ruiSDK` / `mvloglib` / `libcurl` / `hcanvas` | ~14 MB | Qt5 / HDevelop / 采集插件的传递依赖 |

- **额外发现**：原部署脚本会拷 `opencv_world4130d.dll`（**debug 版，126 MB**）。生产包
  只该有 Release 版 `opencv_world4130.dll`，已移除该行——出现「缺 `opencv_world4130d.dll`」
  只可能是拿了 debug 版 exe 去跑。
- **结果**：包体积 **1485 MB → 930 MB**（省 555 MB），自检仍 `71 PASS / 0 FAIL`。
- **回退方式**：若将来启用 HALCON 采集、HDevelop 引擎或 XL 变体，把对应 DLL 加回
  `tools/deploy.ps1` 的 `$halconNeeded` 白名单即可，其余逻辑不变。

## 8. DeepOCR 现场自检：换机后一条命令验证（2026-11-08）

```powershell
# 单张图（默认 mode=2 recognition）
VisionFlowPlatform.exe --selftest-deepocr D:\samples\a.png

# 整个目录（递归子目录）+ 导出 CSV + 限制张数
VisionFlowPlatform.exe --selftest-deepocr D:\samples --mode 2 --min-conf 0.3 --limit 200 --csv result.csv
```

- **递归子目录**：现场样本常按批次/日期分层，只扫一层会漏图（2026-11-09 修正）。
- `--limit`：批量样本很多时先跑前 N 张冒个头，默认 200，防止误扫超大目录。
- 输出每张图的识别文本、词数、平均/最高置信度、耗时；末行汇总含成功/失败数、
  总耗时 / 平均 / 最慢、总词数、平均置信度；失败项另列「失败明细」。
- CSV 列：`file,ok,words,avg_confidence,max_confidence,elapsed_ms,text,error,mode`。
  `file` 用**相对根目录的路径**，避免不同子目录同名文件混淆。
- 「判成功但无词」的提示按模式区分：非 recognition 建议改 `--mode 2`；**已经是
  recognition 时**改提示检查图片/阈值/模型（旧版一律建议改模式，属误导）。
- 退出码：`0` 全成功 / `1` 有失败 / `2` 未找到图片。

**实测（免安装环境：清空 `HALCONROOT`、移除 `PATH` 里的 HALCON）**：

```
DeepOCR 自检: 1 张，mode=2（0=auto/1=detection/2=recognition），minConfidence=0.3
[OK]   deepocr_sample.png  words=1  avg=0.000  max=0.000  502 ms  "HELLO12345"
==== 汇总: 1/1 成功，总耗时 502 ms ====
```

**两个实测结论（务必知道）**：

1. **`auto` / `detection` 模式拿不到识别文本**：这两种模式的返回只含检测结果、没有 `word`
   数组，当前解析逻辑下 `ocrText` 为空（不是坏了，是没解析）。要读字请用 `--mode 2`
   （节点参数 `mode` 也建议选 recognition）。自检工具对「判成功但无词」会给出换模式提示。
2. **`recognition` 模式的置信度不可用**（`avg`/`max` 恒 0）：返回里没有 `confidence` 键。
   这曾导致**默认参数下永远读不到字**——旧实现把缺失置信度当 `0.0`，被默认
   `minConfidence=0.3` 全部过滤掉（只有显式 `--min-conf 0.0` 才出文本）。已修为
   「没有置信度就不过滤」，`avg`/`max` 置 0 表示不可用。要真正用上置信度，需先确认
   HALCON 侧的键名。

## 9. 长稳（soak）现场验证（2026-11-09）

`tools/soak.ps1` 驱动连续模式长跑，观察轮次、失败、句柄数、工作集的增长趋势：

```powershell
# 默认 72 小时；短跑验证用小数小时
powershell -ExecutionPolicy Bypass -File tools\soak.ps1 -Hours 0.5 `
    -SampleSeconds 10 -CsvPath logs\soak_samples.csv
```

- 输出 `logs\soak_report_<时间戳>.txt`（C++ 侧完整报告：轮次/失败轮次/句柄与工作集增量/
  逐节点执行次数与最大耗时）与 `logs\soak_progress.txt`（每秒进度）。
- `-CsvPath` 额外出**每 `-SampleSeconds` 秒一行**的 CSV：
  `timestamp,elapsed_s,handles,working_set_mb`，可直接画图看泄漏趋势。
- 脚本会自动在 `dist\VisionFlowPlatform-rc-*` 里挑**最新的、含 `halconcpp.dll` 的包**作为
  DLL 来源。旧版固定指向 `dist\VisionFlowPlatform`（历史默认目录，早已不产出），
  现场会因 `0xC0000135` 起不来——2026-11-09 修正。
- **短跑实测**：14 秒 / 3372 轮（240.9 轮/秒）/ 0 失败 / 句柄 483→483（Δ0）/
  工作集 46→50 MB（Δ3），CSV 7 行采样；报告与 CSV 均正常产出。

> 判定口径：短跑只证明「此刻无泄漏」；长时劣化要看 72h 的句柄/工作集斜率，
> 而不是单点 Δ。

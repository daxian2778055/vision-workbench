## 0. 修订说明

### 0.1 为什么重写

原始需求文件 `需求.txt` 存在**不可逆的编码损坏**：文件中包含 1520 个 `U+FFFD` 替换符（`EF BF BD` 字节序列）。

**损坏原因**：GBK 编码的中文内容被当作 UTF-8 解码，无法识别的字节被替换为 `U+FFFD` 并重新保存为 UTF-8。这属于**有损转换，原始字节已永久丢失，无法通过任何转码手段恢复**（转码只能改变"怎么看"，不能还原"已经被扔掉的字节"）。

同目录下的 `requirements_decoded.txt` 是早期一次失败的解码尝试产物，同样是乱码，已废弃。

因此本文档**不是对原文的简单转码**，而是基于以下三个来源**重建并全面升级**的需求基线：

1. 原始文件残留的**章节骨架与需求编号体系**（FR / NFR / DR / SR 编号得以保留，保证历史连续性）；
2. 代码库中**已实际实现的能力**（`include/`、`src/`、`src/NodeRegistry.cpp`）；
3. **VisionMaster 4.4** 公开的能力体系（定位 / 测量 / 识别 / 检测 / 深度学习 / 资源管理 / 3D）。

### 0.2 相对原始需求的主要变化

| 维度 | 原始需求（v1） | 本版（v2） |
|------|---------------|-----------|
| 覆盖范围 | 以 UI 交互为主（拖拽、连线、布局、删除） | 覆盖采集→预处理→定位→测量→识别→检测→深度学习→通讯→数据→平台全链路 |
| 对标 | 仅零散提及 VisionMaster | 全生命周期对标 VM 4.4，每条目标注对标模块 |
| 状态可见性 | 无 | 每条需求标注 ✅已实现 / ⚠️部分实现 / ❌未实现 |
| 非功能需求 | 仅性能/可靠性/稳定性 7 条 | 扩展为 7 大类 30+ 条（含安全性、可维护性、国际化） |
| 验收标准 | 无 | 新增可量化验收标准章节 |

## 1. 产品概述

### 1.1 产品定位

一款**图形化、节点式（算子流）的机器视觉算法开发平台**。用户通过拖拽算子、连线构建视觉方案（Scheme），无需编写代码即可完成工业现场的**定位、测量、识别、检测**四大类任务。

### 1.2 目标用户

| 角色 | 特征 | 核心诉求 |
|------|------|---------|
| 视觉调试工程师 | 熟悉工艺，不写代码 | 拖拽即用、参数直观、结果可视 |
| 算法工程师 | 会 C++/Python | 可自定义算子、可脚本扩展 |
| 设备集成商 | 需对接 PLC/机器人 | 通讯矩阵完备、稳定 7×24 |
| 产线操作工 | 只操作不配置 | 运行界面简洁、权限受限 |

### 1.3 对标目标

**一句话目标**：在"定位 / 测量 / 识别 / 检测"四大场景上达到 VisionMaster 4.4 的**可用性与算子覆盖度**，并在**开放性**（脚本、SDK、自定义算子）与**自主可控**（OpenCV 主线）上形成差异化优势。

**分阶段目标**：

| 阶段 | 目标 | 衡量标准 |
|------|------|---------|
| 近期 | 补齐 VM 4.4 四大场景的核心算子与交互体验 | 覆盖 VM 4.4 常用算子 ≥ 80% |
| 中期 | 深度学习全栈 + 3D + 工业通讯矩阵 | 支持检测/分割/异常检测；支持 OPC UA、S7 |
| 长期 | 平台生态（SDK、算子市场、行业方案包） | 可提供二次开发 SDK 与算子插件规范 |

### 1.4 术语表

| 术语 | 说明 |
|------|------|
| 算子（Node / Tool） | 流程中最小的功能单元，如"模板匹配""卡尺测量" |
| 方案（Scheme / Solution） | 一个完整的视觉工程，存储为 `.vfp` 文件 |
| 流程（Flow） | 方案中的一个标签页，包含一组相互连线的算子 |
| 模块号 | 算子在流程中的序号，用于参数引用（如 `{1.角度}`） |
| ROI | 感兴趣区域，限定算法作用的图像范围 |
| Region / XLD | HALCON 中的区域 / 亚像素轮廓数据 |
| 配方（Recipe） | 同一方案下不同产品型号的参数集合 |
| 运行界面 | 面向操作工的简化界面，由 RuntimeInterfaceDesigner 设计 |
| 软触发 / 硬触发 | 由软件指令 / 由外部硬件信号触发采集 |

> FR1.9 实现口径：分组是**纯视觉容器**（`NodeGroupItem`）——不参与执行、不改节点/连线、不发图结构信号；
> 成员用**模块号**标识（跨存盘/撤销稳定），随方案保存（`extras` 的 `nodeGroups`）并随撤销快照回滚。
> 入口：画布空白右键「创建分组」/ 「编辑 → 创建分组」(Ctrl+G) / 「解散分组」(Ctrl+Shift+G)；
> 分组标题栏可拖动（组内其余区域仍可框选算子），右键改名，拖动成员时框体自动跟随。
> 选中分组框按 Delete = 解散（**只删框，不删算子**）。
> **Group 折叠（2026-09-23 已交付）**：双击标题栏（或右键「折叠/展开分组」、编辑菜单同项）把分组收成
> 一条标题栏，组内算子与其相关连线一并隐藏、框体宽度与位置不变（留作"这段有多宽"的线索），
> 折叠状态随方案保存并可撤销。可见性由 `FlowScene::refreshGroupVisibility` **统一重算**
> （连线两端分属不同分组、多组同时折叠时才不会算错；隐藏的算子会被取消选中，避免"删掉看不见的算子"）；
> 折叠是**纯显示**（真跑流程验证执行不受影响），且**解散分组时必定恢复成员可见性**
> （否则"解散"后算子会凭空消失）。编辑锁定（运行中）仍允许折叠/展开——它是查看动作。

> 依据 2026-09-14 代码审查（`FlowExecutor.cpp` / `MvsImageSourceNode.cpp` / `DelayNode.cpp` / `LoopNode.cpp`）。**本轮未修改代码**，仅记录风险。结论：当前平台**不可宣称达到 VM 4.4 工业交付水平**，须先修复以下问题。

| 编号 | 优先级 | 问题 | 位置 | 影响 |
|------|--------|------|------|------|
| E1 | P1 | 参数引用 `{模块号.参数名}` 解析结果直接 `setParam` 写回节点参数，未保留表达式；第二轮上游变化下游仍用旧值，保存方案还可能把引用存成常量 | `FlowExecutor.cpp:547` | 检测正确性（参数语义漂移） |
| E2 | P1 | 未激活分支只清节点输出、未清 `m_nodeData`；`propagateData` 优先读缓存，空数据不覆盖下游旧输入 → 汇合节点可能用上一件产品数据 | `FlowExecutor.cpp:820` | 检测正确性（跨轮串数据） |
| E3 | P1 | 多流程共享全局 `s_currentInstance`，相机据此判断硬触发模式与停止状态；切到流程 B 后流程 A 的相机可能按 B 的状态等待/退出 | `FlowExecutor.cpp:119`、`MvsImageSourceNode.cpp:427` | 流程隔离 / 稳定性 |
| E4 | P1 | 延时节点 `QThread::msleep` 不可取消；执行器析构仅 `wait(5000)`，超时仍销毁，线程可能访问已释放成员 | `DelayNode.cpp:34`、`FlowExecutor.cpp:58` | 运行稳定性（崩溃路径） |
| E5 | P1 | `LoopNode::run()` 初始 `moduleStatus=false` 会被基类判失败；`runLoopBody` 强制激活所有循环体、绕过条件分支、不检查暂停/停止 | `LoopNode.cpp:21`、`FlowExecutor.cpp:749` | 循环 / 分支正确性 |
| E6 | P2 | 连续与硬触发模式每轮固定 `msleep(50)`，即便算法几乎不耗时也被限到约 20 轮/秒 | `FlowExecutor.cpp:381` | 吞吐性能 |

**测试覆盖缺口**：现有 Release 构建 5 个 CTest 通过，但 `integration_test.cpp:45` 主要校验节点创建/端口/空输入，**未真正执行连接后的端到端流程**，不能覆盖 E1–E6。需新增真实集成测试：连续运行多轮参数引用、条件分支汇合空值传播、循环+分支、双流程触发隔离、延时安全停止。

**修复顺序建议**：① 修复执行正确性（E1/E2/E5）、流程隔离（E3）、安全停止（E4）；② 补齐上述真实集成测试；③ 再扩展算法数量。

## 7. 验收标准

| 编号 | 场景 | 验收标准 |
|------|------|---------|
| AC1 | 定位引导 | 用模板匹配+位置修正，对同一样本 100 次重复，位置标准差 ≤ 0.05 px，角度标准差 ≤ 0.05° |

| AC4 | OCR | 印刷体字符识别率 ≥ 99%；DL OCR 在复杂背景下 ≥ 95% |
| AC5 | 缺陷检测 | 标准缺陷样本集漏检率 ≤ 0.1%，过杀率 ≤ 1% |
| AC6 | 通讯 | PLC/Modbus 连续通讯 24h 无丢包，掉线后 3s 内自动重连 |
| AC7 | 稳定性 | 7×24 连续运行 72h，内存增长 ≤ 5%，无崩溃 |
| AC8 | 易用性 | 新用户参照快速入门手册，30 分钟内完成一个采图→定位→测量→输出方案 |
| AC9 | 兼容性 | 旧版本 `.vfp` 方案可被新版本正确加载并运行 |
| AC10 | 安全 | 恶意脚本（越权文件访问/无限循环）被沙箱拦截或超时终止，且留下审计记录 |

### 8.2 编码规范（防止需求文档再次损坏）

1. 所有文本资产**统一 UTF-8 无 BOM** 保存。
2. 禁止用"另存为 ANSI / GBK"的方式保存中文文档。
3. 发现乱码时**先不要保存**——保存会把替换符写死，造成永久损坏；应先确认正确编码再另存。
4. Git 提交统一 UTF-8；建议为本仓库配置 `.gitattributes` 明确文本编码。
